# 队列基础应用

队列（Queue）遵循先进先出（FIFO）：先进入队列的元素先被处理。C# 的 `System.Collections.Generic.Queue<T>` 从 .NET Framework 2.0 起提供。

**版本说明：示例使用 C# 12/.NET 8（`net8.0`）。** 队列用于任务调度、BFS、树的层序遍历和生产者/消费者流水线。

## 1. 复杂度与接口

`Enqueue`、`Dequeue`、`Peek`、`TryDequeue` 和 `TryPeek` 的均摊时间复杂度为 `O(1)`；遍历全部元素为 `O(n)`，存储空间为 `O(n)`。数组扩容会复制元素，但摊销后入队仍为常数时间。普通 `Queue<T>` 不保证线程安全。

## 2. 基础用法：按顺序处理任务

`.NET 6` 新增 `TryDequeue` 和 `TryPeek`，可把“检查后取出”合并为一次操作，代码更清晰。下面示例把任务按提交顺序执行。

```csharp
var jobs = new Queue<string>(new[] { "编译", "测试", "打包" });
while (jobs.TryDequeue(out string? job))
{
    Console.WriteLine($"执行：{job}");
}
```

## 3. 基础用法：无权图 BFS

BFS 使用队列按层访问顶点。顶点第一次入队时记录距离，可保证边权均为 1 的图中得到最短边数。邻接表实现的时间复杂度为 `O(V + E)`，额外空间 `O(V)`。

```csharp
public static int[] Distances(
    IReadOnlyList<IReadOnlyList<int>> graph, int source)
{
    if ((uint)source >= (uint)graph.Count)
        throw new ArgumentOutOfRangeException(nameof(source));

    int[] distance = new int[graph.Count];
    Array.Fill(distance, -1);
    var queue = new Queue<int>();
    distance[source] = 0;
    queue.Enqueue(source);

    while (queue.TryDequeue(out int u))
    {
        foreach (int v in graph[u])
        {
            if ((uint)v >= (uint)graph.Count)
                throw new ArgumentOutOfRangeException(nameof(graph));
            if (distance[v] != -1) continue; // 入队时标记，避免重复入队
            distance[v] = distance[u] + 1;
            queue.Enqueue(v);
        }
    }
    return distance;
}
```

树的层序遍历也是同一模式：队列元素可携带节点和层号，或在每层开始时读取 `queue.Count` 作为该层元素数量。

## 4. 进阶：异步生产者/消费者（.NET 8）

多线程任务流水线不应通过普通 `Queue<T>` 加手写锁来实现。`System.Threading.Channels` 提供异步读写和完成通知；有界通道还能在队列达到容量时自动施加背压。Channels 在 .NET Core 3.0 进入共享框架。

```csharp
using System.Threading.Channels;

var channel = Channel.CreateBounded<string>(capacity: 100);

Task producer = Task.Run(async () =>
{
    try
    {
        for (int i = 0; i < 1_000; i++)
            await channel.Writer.WriteAsync($"job-{i}");
    }
    finally
    {
        channel.Writer.TryComplete();
    }
});

Task consumer = Task.Run(async () =>
{
    await foreach (string job in channel.Reader.ReadAllAsync())
        Process(job);
});

await Task.WhenAll(producer, consumer);
static void Process(string job) => Console.WriteLine(job);
```

生产者发生异常时，应将异常传给 `TryComplete(exception)`，让消费者在 `ReadAllAsync` 中观察到失败；无条件吞掉异常会让任务看似正常结束。

## 5. 进阶：优先级与双端队列的选择

需要按优先级而不是到达顺序取出元素时，应使用 .NET 6 引入的 `PriorityQueue<TElement,TPriority>`；需要两端插入/删除时使用 `Deque` 实现或 `LinkedList<T>`，不要通过反复移动 `Queue<T>` 模拟。固定窗口最值问题应使用单调队列，详见 [单调队列](./单调队列（Monotonic%20Queue）.md)。

## 6. 常见错误

1. 空队列直接调用 `Dequeue` 或 `Peek`；使用 `TryDequeue`、`TryPeek` 或先判断 `Count`。
2. BFS 出队时才标记访问，造成同一顶点多次入队；通常在入队时标记。
3. 用队列处理不同权重边的最短路；应改用 Dijkstra、0-1 BFS 或其他适合算法。
4. 多线程共享 `Queue<T>`；应使用 `ConcurrentQueue<T>`、`Channel<T>` 或显式同步。
5. 生产者结束后不调用 `Complete/TryComplete`，消费者会一直等待，无法正常收尾。
