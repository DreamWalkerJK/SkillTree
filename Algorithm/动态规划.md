# 动态规划（Dynamic Programming）

动态规划把一个问题拆成相互重叠的子问题，保存子问题结果，避免重复计算。它适合满足两个条件的问题：子问题的最优解可以组成原问题的最优解（最优子结构），并且不同状态会重复出现（重叠子问题）。

**示例环境：C# 12、.NET 8（`net8.0`）。** 动态规划是算法方法，不依赖特定运行时；示例使用数组、字典和 `ReadOnlySpan<T>` 等 BCL 类型。

## 1. 建模步骤与复杂度

建模时按以下顺序确定：

1. 定义状态 `dp[...]`：它必须包含足以决定后续选择的信息。
2. 写出状态转移：从规模更小的状态推导当前状态。
3. 确定初始状态和不可达值。
4. 选择计算顺序（自顶向下记忆化或自底向上迭代）。
5. 估算状态数量与每个状态的转移次数，得到时间和空间复杂度。

状态定义过少会丢失必要信息，定义过多则导致状态数量爆炸。不可达状态应使用不会与合法答案混淆的哨兵值，并在转移前检查哨兵，避免溢出。

## 2. 基础用法：爬楼梯

每次走 1 或 2 级台阶。令 `dp[i]` 表示到达第 `i` 级的方案数，则 `dp[i] = dp[i - 1] + dp[i - 2]`。只需保留最近两个状态，空间从 `O(n)` 降到 `O(1)`：

```csharp
public static long CountWays(int stairs)
{
    if (stairs < 0) throw new ArgumentOutOfRangeException(nameof(stairs));
    if (stairs <= 1) return 1;

    long previous = 1; // dp[0]
    long current = 1;  // dp[1]
    for (int i = 2; i <= stairs; i++)
        (previous, current) = (current, checked(previous + current));
    return current;
}
```

时间复杂度为 `O(n)`，空间复杂度为 `O(1)`。如果结果可能超过 `long`，应改用大整数或对指定模数取模，而不是静默溢出。

## 3. 记忆化搜索：带代价的路径

自顶向下写法保留递归的自然结构，使用字典缓存已经求出的状态。下面求网格从左上角到右下角、只能向右或向下时的最小代价：

```csharp
public static int MinPath(IReadOnlyList<int> cells, int rows, int columns)
{
    if (rows <= 0 || columns <= 0 || cells.Count != rows * columns)
        throw new ArgumentException("网格尺寸与数据长度不一致");

    var memo = new Dictionary<(int Row, int Column), int>();

    int Solve(int row, int column)
    {
        if ((uint)row >= (uint)rows || (uint)column >= (uint)columns)
            return int.MaxValue / 4;
        if (row == rows - 1 && column == columns - 1)
            return cells[row * columns + column];
        if (memo.TryGetValue((row, column), out int cached)) return cached;

        int right = Solve(row, column + 1);
        int down = Solve(row + 1, column);
        int result = cells[row * columns + column] + Math.Min(right, down);
        memo[(row, column)] = result;
        return result;
    }

    return Solve(0, 0);
}
```

状态数为 `rows * columns`，每个状态只计算一次，因此时间和空间复杂度均为 `O(rows * columns)`。递归深度过大时改用迭代表，避免栈溢出。

## 4. 经典进阶：0/1 背包

每件物品最多选择一次。`dp[c]` 表示容量不超过 `c` 时的最大价值。容量必须从大到小遍历，否则同一件物品会在一次循环中被重复使用：

```csharp
public static int Knapsack01(
    ReadOnlySpan<int> weights,
    ReadOnlySpan<int> values,
    int capacity)
{
    if (weights.Length != values.Length || capacity < 0)
        throw new ArgumentException("输入长度或容量无效");

    var dp = new int[capacity + 1];
    for (int item = 0; item < weights.Length; item++)
    {
        int weight = weights[item];
        if (weight < 0) throw new ArgumentOutOfRangeException(nameof(weights));
        for (int c = capacity; c >= weight; c--)
            dp[c] = Math.Max(dp[c], dp[c - weight] + values[item]);
    }
    return dp[capacity];
}
```

时间复杂度为 `O(nC)`，空间复杂度为 `O(C)`，其中 `n` 是物品数，`C` 是容量。容量很大而物品价值总和较小时，可改用“按价值建状态”；应根据输入范围选择维度。

## 5. LIS：恢复最优解

最长严格递增子序列（LIS）可以用 `O(n²)` 的基础转移：`dp[i]` 表示以 `i` 结尾的最长长度，并记录前驱以恢复序列。需要大规模输入时，使用二分维护 tails 可降到 `O(n log n)`，但恢复逻辑更复杂，必须单独测试重复元素。

```csharp
public static int[] LongestIncreasingSubsequence(ReadOnlySpan<int> values)
{
    if (values.Length == 0) return [];
    int n = values.Length;
    var length = new int[n];
    var previous = new int[n];
    Array.Fill(length, 1);
    Array.Fill(previous, -1);

    int best = 0;
    for (int i = 0; i < n; i++)
    {
        for (int j = 0; j < i; j++)
        {
            if (values[j] < values[i] && length[j] + 1 > length[i])
            {
                length[i] = length[j] + 1;
                previous[i] = j;
            }
        }
        if (length[i] > length[best]) best = i;
    }

    var result = new int[length[best]];
    for (int k = result.Length - 1, index = best; index >= 0; k--, index = previous[index])
        result[k] = values[index];
    return result;
}
```

## 6. 常见错误与选型

1. 没有先写清状态含义，代码中的 `dp` 下标只凭感觉变化。
2. 0/1 背包把容量从小到大遍历，误把问题变成完全背包。
3. 把不可达状态设为 `int.MaxValue` 后直接相加，产生整数溢出。
4. 只返回最优值，却忘记保存前驱，导致无法恢复方案。
5. 递归记忆化时漏掉一个维度，缓存键不足以区分状态。
6. 把所有问题都套进动态规划；若状态没有重叠，排序、贪心或双指针可能更简单。

当状态转移依赖固定长度窗口时，可结合 [单调队列](<数据结构/单调队列（Monotonic Queue）.md>) 优化；当状态是图上的可达关系时，可结合 [BFS](<图论/广度优先搜索 BFS.md>) 或 [Dijkstra](<图论/Dijkstra 最短路径算法.md>) 选择更合适的模型。
