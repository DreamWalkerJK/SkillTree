# 动态编程（dynamic）

> 版本信息：.NET 8（C# 12）。`dynamic` 与动态绑定于 C# 4.0/.NET Framework 4.0 引入；DLR（Dynamic Language Runtime）由 .NET 4.0 提供。示例目标为 `net8.0`，可迁移到 .NET 10；.NET 11 Preview 仅作兼容性提示。

本文讨论 C# 的 `dynamic` 运行时绑定；算法中的动态规划（Dynamic Programming）请参阅 [算法动态规划](../../Algorithm/动态规划.md)。

dynamic 让编译器把成员解析推迟到运行时。运行时根据实际对象类型选择成员，失败时抛出 RuntimeBinderException。它适合 COM、脚本、JSON 形状不固定的数据和动态语言互操作，不应取代稳定的接口。

## 基础用法

~~~csharp
dynamic value = 10;
Console.WriteLine(value + 2); // 12
value = "dotnet";
Console.WriteLine(value.ToUpperInvariant());

try
{
    Console.WriteLine(value.NotExists());
}
catch (Microsoft.CSharp.RuntimeBinder.RuntimeBinderException ex)
{
    Console.Error.WriteLine(ex.Message);
}
~~~

dynamic 表达式的结果也是 dynamic，编译器不会检查拼写、参数数量和返回类型。需要安装 Microsoft.CSharp 程序集（SDK 风格项目通常已隐式引用）。

## 与 object、反射的区别

object 只提供静态类型成员，调用前必须转换；dynamic 由 DLR 缓存调用站点；反射则显式查找 MethodInfo。固定契约优先接口或泛型，偶发动态调用可封装在很小的适配层中。

~~~csharp
static object ReadObject(object input) => input;
static dynamic ReadDynamic(dynamic input) => input;

object boxed = ReadObject("abc");
string text = (string)boxed;       // 显式转换
dynamic dynamicValue = ReadDynamic("abc");
int length = dynamicValue.Length;  // 运行时绑定
~~~

## ExpandoObject 与动态成员

ExpandoObject 实现 IDictionary<string, object?>，可在运行时增加成员。它是有意放弃编译期检查的可变数据结构，跨线程使用时应复制或加锁。

~~~csharp
using System.Dynamic;
using System.Collections.Generic;

dynamic request = new ExpandoObject();
request.Name = "Ada";
request.Tags = new[] { "csharp", "dotnet" };

var map = (IDictionary<string, object?>)request;
if (map.TryGetValue("Name", out object? name))
    Console.WriteLine(name);
~~~

## 高级用法：自定义 DynamicObject

继承 DynamicObject 可以实现属性、方法和索引器的自定义分派。下面示例把键映射到字典，并对不存在的键返回 null。

~~~csharp
using System.Dynamic;

public sealed class DynamicBag : DynamicObject
{
    private readonly Dictionary<string, object?> _values = [];

    public override bool TrySetMember(
        SetMemberBinder binder, object? value)
    {
        _values[binder.Name] = value;
        return true;
    }

    public override bool TryGetMember(
        GetMemberBinder binder, out object? result)
    {
        // 返回 true 表示动态绑定成功；不存在的键按 null 处理。
        _values.TryGetValue(binder.Name, out result);
        return true;
    }
}

dynamic bag = new DynamicBag();
bag.Count = 3;
int count = bag.Count;
~~~

DLR 会缓存同一调用点的绑定规则（多态内联缓存）。对象类型变化过多会导致缓存失效和额外开销；热点路径可把动态结果转换为强类型 DTO。

## JSON 与 COM 注意事项

System.Text.Json 默认反序列化为 JsonElement 或 JsonNode，而不是可安全访问任意 dynamic 属性：

~~~csharp
using System.Text.Json;
using System.Text.Json.Nodes;

JsonNode? node = JsonNode.Parse("""{"id":42}""");
int id = node?["id"]?.GetValue<int>() ?? 0;
~~~

COM 自动化在 Windows 上可使用 dynamic，但要处理 HRESULT、线程单元和资源释放。NativeAOT、裁剪发布和沙箱环境通常不支持需要运行时代码生成的动态绑定；可改用源生成器或显式接口。

## 实践建议

- 将 dynamic 限制在外部数据适配层，立即转换为领域类型。
- 对运行时绑定失败编写测试，记录实际类型和调用点。
- 不把不可信输入直接作为成员名或方法名执行。
- 性能敏感代码使用委托缓存、泛型或源生成代码。
