# .NET 内存管理

> 版本信息：托管 GC 自 .NET 1.0；Server/Workstation GC 早期即提供；LOH 压缩于 .NET Framework 4.5.1；Pinned Object Heap（POH）于 .NET 5；NativeMemory API 于 .NET 6；.NET 8 改善动态 PGO、GC 和 NativeAOT。示例使用 C# 12、目标框架 `net8.0`，可迁移到 .NET 10；.NET 11 Preview 需按目标 SDK 验证。

.NET 托管堆由 GC 自动回收对象。开发者仍需管理非托管资源、对象生命周期和分配速率。

## GC 基础

短命对象通常位于第 0 代，存活后晋升到第 1、2 代；大于约 85 KB 的对象进入大对象堆（阈值由运行时实现决定）。LOH 回收成本较高，频繁创建大数组会造成暂停和碎片。

~~~csharp
byte[] buffer = GC.AllocateUninitializedArray<byte>(4096);
Console.WriteLine(GC.GetGeneration(buffer));
~~~

Server GC 适合吞吐型服务器，Workstation GC 适合交互应用。通过运行时配置切换，并以实际延迟和吞吐指标验证。

## IDisposable 与终结器

实现 IDisposable 释放文件、套接字、SafeHandle 等资源；终结器只是最后保险，不应承担及时释放：

~~~csharp
public sealed class NativeBuffer : IDisposable
{
    private nint _pointer;
    private bool _disposed;

    public NativeBuffer(int length)
        => _pointer = System.Runtime.InteropServices.Marshal.AllocHGlobal(length);

    public void Dispose()
    {
        if (_disposed) return;
        _disposed = true;
        if (_pointer != 0)
        {
            System.Runtime.InteropServices.Marshal.FreeHGlobal(_pointer);
            _pointer = 0;
        }
        GC.SuppressFinalize(this);
    }
}
~~~

优先封装 SafeHandle，避免自己编写终结器。异步资源实现 IAsyncDisposable 并在 finally 中 await DisposeAsync。

## 池化与固定

ArrayPool<T>、ObjectPool<T> 减少分配，但租赁对象归还前要清理状态。fixed、GCHandle.Alloc(..., Pinned) 会阻止对象移动；固定时间过长会降低 GC 压缩效率。POH 适合长期固定的大缓冲区，但仍需测量。

## NativeMemory 与诊断

.NET 6 的 NativeMemory.Alloc/Free 用于跨平台非托管分配；必须成对释放。使用 dotnet-counters 观察 allocation-rate、gc-heap-size、gen-2-gc-count 和 time-in-gc；用 dotnet-dump、PerfView 或 JetBrains dotMemory 定位泄漏和保留路径。

~~~csharp
using System.Runtime.InteropServices;

// 项目文件需设置 <AllowUnsafeBlocks>true</AllowUnsafeBlocks>
unsafe
{
    nint memory = (nint)NativeMemory.Alloc((nuint)1024);
    try
    {
        NativeMemory.Clear((void*)memory, 1024);
    }
    finally
    {
        NativeMemory.Free((void*)memory);
    }
}
~~~

## 高级调优

- 先减少不必要的对象图和字符串复制，再考虑池化。
- 使用 readonly struct、Span 和 Memory 传递切片，避免临时数组。
- 监控第 2 代集合和 LOH 分配，避免只看平均延迟。
- 生产环境保留 GC 事件和分配堆栈的采样能力，出现尾延迟升高时可回溯。
- AOT、容器内存限制和 cgroup 感知会影响 GC 预算，部署配置应与压测环境一致。
