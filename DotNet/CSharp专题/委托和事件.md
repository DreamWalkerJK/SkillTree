# 委托和事件

> 版本信息：.NET 10（C# 14）。委托和 `event` 自 C# 1.0/.NET 1.0 可用；`Predicate<T>`、单参数 `Action<T>` 和 `EventHandler<TEventArgs>` 于 .NET 2.0 引入；无参数 `Action`、更多参数的 `Action` 重载及 `Func` 委托于 .NET 3.5 引入。示例目标为 `net10.0`。

委托是对方法签名的类型安全引用，事件是在委托之上提供“发布者可调用、订阅者只能增删”的封装。

## 基础用法

~~~csharp
using System;

public sealed class OrderService
{
    public event EventHandler<OrderCreatedEventArgs>? OrderCreated;

    public void Create(int id)
    {
        OrderCreated?.Invoke(this, new OrderCreatedEventArgs(id));
    }
}

public sealed class OrderCreatedEventArgs(int id) : EventArgs
{
    public int Id { get; } = id;
}

public static class Demo
{
    public static void Run()
    {
        var service = new OrderService();
        service.OrderCreated += (_, e) => Console.WriteLine("订单：" + e.Id);
        service.Create(1);
    }
}
~~~

委托可以组合、多播和异步化：

~~~csharp
using System;

Func<int, int, int> add = (x, y) => x + y;
Func<int, int, int> multiply = (x, y) => x * y;
Func<int, int, int> pipeline = add + multiply;
int result = pipeline(2, 3); // 多播委托返回最后一个结果
~~~

多播返回值只保留最后一次调用；有返回值时通常不要组合委托。

## 高级用法

定义强类型委托可表达领域语义：

~~~csharp
using System;
using System.Collections.Generic;
using System.Threading;
using System.Threading.Tasks;

public delegate ValueTask MessageHandler(
    ReadOnlyMemory<byte> payload, CancellationToken cancellationToken);

public sealed class MessageBus
{
    private readonly List<MessageHandler> _handlers = [];

    public void Subscribe(MessageHandler handler) => _handlers.Add(handler);

    public async ValueTask PublishAsync(
        ReadOnlyMemory<byte> payload, CancellationToken token)
    {
        foreach (MessageHandler handler in _handlers.ToArray())
            await handler(payload, token);
    }
}
~~~

事件订阅会延长订阅者生命周期，长期发布者应提供 Dispose 或弱事件模式。跨线程触发事件时复制委托快照，并保证处理程序异常不会阻断其他订阅者。发布者可以把调用逻辑封装在类型内部：

~~~csharp
using System.Linq;
using Microsoft.Extensions.Logging;

public sealed class SafeOrderService
{
    public event EventHandler<OrderCreatedEventArgs>? OrderCreated;

    public void Publish(OrderCreatedEventArgs args, ILogger logger)
    {
        EventHandler<OrderCreatedEventArgs>? snapshot = OrderCreated;
        foreach (EventHandler<OrderCreatedEventArgs> handler in
                 snapshot?.GetInvocationList()
                    .Cast<EventHandler<OrderCreatedEventArgs>>() ?? [])
        {
            try { handler(this, args); }
            catch (Exception ex) { logger.LogError(ex, "事件处理失败"); }
        }
    }
}
~~~

在 ASP.NET Core 中，跨进程通知应使用消息总线而非内存事件；事件名称使用过去时态（OrderCreated）表示已经发生的事实。

## 工程示例：事件订阅的生命周期

事件发布者通常比订阅者存活更久。订阅短生命周期对象后必须在释放时取消订阅，否则发布者会一直持有订阅者，形成内存泄漏或向已失效对象发送通知。

~~~csharp
public sealed class OrderBus
{
    public event EventHandler<OrderCreatedEventArgs>? OrderCreated;

    public void Publish(Order order)
        => OrderCreated?.Invoke(this, new OrderCreatedEventArgs(order));
}

public sealed class OrderCreatedEventArgs(Order order) : EventArgs
{
    public Order Order { get; } = order;
}

public sealed class OrderProjection(OrderBus bus) : IDisposable
{
    public OrderProjection() : this(new OrderBus()) { }
    public void Start() => bus.OrderCreated += OnOrderCreated;
    private void OnOrderCreated(object? sender, OrderCreatedEventArgs e) { }
    public void Dispose() => bus.OrderCreated -= OnOrderCreated;
}

public sealed record Order(Guid Id);
~~~

委托参数应尽量表达稳定契约；需要返回多个结果时优先定义命名结果类型。事件处理程序中的异常不能被发布者随意吞掉，多个订阅者的失败传播策略应在总线层明确规定。
