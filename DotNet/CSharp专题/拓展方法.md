# 拓展方法（扩展方法）

> 版本信息：.NET 10（C# 14）。扩展方法于 C# 3.0/.NET 3.5 引入；扩展块语法是 C# 14/.NET 10 的新特性。本文示例目标为 `net10.0`，同时展示传统静态扩展方法与扩展块写法。

扩展方法是静态类中的静态方法，第一个参数以 this 修饰。编译器把 receiver.Method(args) 重写为 StaticClass.Method(receiver, args)，不会修改原类型或参与虚方法分派。

## 基础用法

~~~csharp
public static class StringExtensions
{
    public static bool IsNullOrWhiteSpace(this string? value)
        => string.IsNullOrWhiteSpace(value);

    public static string Truncate(this string value, int maxLength)
    {
        ArgumentNullException.ThrowIfNull(value);
        if (maxLength < 0) throw new ArgumentOutOfRangeException(nameof(maxLength));
        return value.Length <= maxLength ? value : value[..maxLength];
    }
}

string shortText = "long text".Truncate(4);
~~~

扩展方法必须在作用域中可见；使用 using 导入包含它的命名空间。实例成员优先于扩展方法，多个同名扩展可能导致编译歧义。

## 泛型和约束

~~~csharp
public static class EnumerableExtensions
{
    public static bool None<T>(
        this IEnumerable<T> source,
        Func<T, bool>? predicate = null)
    {
        ArgumentNullException.ThrowIfNull(source);
        return predicate is null
            ? !source.Any()
            : !source.Any(predicate);
    }
}
~~~

扩展方法应保持无状态、参数顺序符合 .NET 约定，并对 null 行为做出明确说明。不要为每个小操作创建层层扩展，避免 API 发现困难。

## 高级用法：扩展块（C# 14/.NET 10）

C# 14 提供 extension block 语法，把同一类型的多个扩展成员集中在一个声明中。以下示例需要 .NET 10 SDK 和对应语言版本，.NET 8 编译器不能使用：

~~~csharp
// 示例语法，需 C# 14 / .NET 10 及以上 SDK
public static class DateOnlyExtensions
{
    extension(DateOnly date)
    {
        public bool IsWeekend => date.DayOfWeek is
            DayOfWeek.Saturday or DayOfWeek.Sunday;

        public DateOnly NextDay() => date.AddDays(1);
    }
}
~~~

若项目必须支持旧目标框架，请继续使用传统 static class + this 参数；扩展块需要 C# 14 编译器。

## 与接口、LINQ 的关系

扩展方法可以为接口提供默认工具，但不能访问实现类型的私有字段，也不能覆盖现有实例成员。LINQ 的 Where、Select 等全部是扩展方法；调用 IQueryable<T> 扩展时，表达式树重载可能优先于 Func 重载。

## 实践建议

- 名称使用动作或谓词，避免与未来实例成员冲突。
- 对热路径避免隐式枚举多次；在文档中说明是否延迟执行。
- 公共库扩展方法应提供 XML 文档、参数验证和单元测试。

## 工程示例：为领域类型提供查询扩展

扩展方法适合表达对已有类型的通用操作，但不应隐藏网络、数据库和文件 I/O。下面的方法只组合内存查询，调用方可以清楚看到延迟执行行为。

~~~csharp
public static class InvoiceQueryExtensions
{
    public static IEnumerable<Invoice> Overdue(
        this IEnumerable<Invoice> source, DateOnly today)
        => source.Where(x => !x.Paid && x.DueDate < today);
}

public sealed record Invoice(
    string Number, DateOnly DueDate, bool Paid);
~~~

如果扩展方法需要依赖配置、日志或数据库连接，应改为注入服务。C# 14 扩展块可以集中声明多个成员，但仍然遵循静态分派和命名空间可见性规则。

## 异步扩展与执行位置

同步查询和异步查询应使用不同名称，不能只靠返回类型重载。异步扩展把取消令牌传到真正执行 I/O 的 API，不在内部调用阻塞等待。

~~~csharp
public static class InvoiceAsyncExtensions
{
    public static async Task<IReadOnlyList<Invoice>> ToOverdueListAsync(
        this IQueryable<Invoice> source,
        DateOnly today,
        CancellationToken cancellationToken = default)
    {
        ArgumentNullException.ThrowIfNull(source);
        // EF Core 等提供程序提供 ToListAsync；不要在此处先 AsEnumerable。
        return await source
            .Where(x => !x.Paid && x.DueDate < today)
            .ToListAsync(cancellationToken);
    }
}
~~~

如果扩展库不希望依赖 EF Core，可以改为接收一个带取消令牌的异步委托，由调用方决定查询实现。公共扩展应说明是否延迟执行、是否多次枚举源集合、何时物化以及取消和异常语义。测试应覆盖空参数、空序列、重复枚举和命名空间冲突。
