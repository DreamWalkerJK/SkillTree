# 模式匹配

> 版本信息：.NET 8（C# 12）。类型模式和常量模式于 C# 7.0；属性、元组和位置模式于 C# 8.0；关系与逻辑模式于 C# 9.0；列表模式于 C# 11/.NET 7；C# 12/.NET 8 增加集合表达式等配套语法。示例目标为 `net8.0`，可迁移到 .NET 10；.NET 11 Preview 仅作兼容性提示。

模式匹配把类型测试、解构和条件判断组合为表达式，适合解析输入、实现状态机和编写穷举分支。

## 基础模式

~~~csharp
static string Format(object? value) => value switch
{
    null => "空",
    int number => "整数：" + number,
    string { Length: 0 } => "空字符串",
    string text => "文本：" + text,
    _ => "其他"
};
~~~

is 模式同时完成判断和变量声明：

~~~csharp
if (response is HttpResponseMessage { IsSuccessStatusCode: true } ok)
{
    Console.WriteLine(ok.StatusCode);
}
~~~

## 关系和逻辑模式

C# 9 支持 >、<= 等关系模式以及 and、or、not：

~~~csharp
static string Classify(int score) => score switch
{
    < 0 or > 100 => "非法",
    >= 90 => "优秀",
    >= 60 => "及格",
    _ => "不及格"
};

if (value is not null and not "")
    Console.WriteLine(value);
~~~

编译器会检查部分不可达分支；写复杂条件时保持分支互斥，必要时使用 when 保护条件。

## 属性、位置和元组模式

~~~csharp
public readonly record struct Point(int X, int Y);

static bool InFirstQuadrant(Point point) => point is { X: > 0, Y: > 0 };

static string Route(Point point) => point switch
{
    (0, 0) => "原点",
    { X: > 0, Y: 0 } => "正 X 轴",
    { X: < 0, Y: < 0 } => "第三象限",
    _ => "其他"
};
~~~

位置模式要求类型提供 Deconstruct 方法或 positional record。属性模式不会调用属性 setter，适合对不可变对象进行安全检查。

## 列表模式

C# 11 列表模式匹配数组、List<T> 等可计数并可索引的类型：

~~~csharp
static string Parse(ReadOnlySpan<int> values) => values switch
{
    [] => "空",
    [var only] => "单项：" + only,
    [1, 2, .. var rest] => "前缀为 1,2，剩余 " + rest.Length,
    [_, _, > 0] => "三项且末项为正",
    _ => "其他"
};
~~~

列表模式会读取 Length/Count 和索引器；对昂贵索引器要注意重复访问。

## 穷举性与 null

switch 表达式应覆盖所有可能输入；使用 _ 作为兜底并记录异常数据。可空引用类型分析与模式匹配互相补充，但模式并不替代业务校验。

~~~csharp
string? input = Console.ReadLine();
string normalized = input is { Length: > 0 } text
    ? text.Trim()
    : "default";
~~~

## 高级实践

- 用模式表达领域状态，避免深层 if/else。
- 将副作用放在分支外；模式本身只负责判定和提取。
- 对用户输入先做结构模式匹配，再做数值和权限校验。
- 复杂规则可用策略对象或表达式树，避免一个 switch 演变成难以测试的巨型函数。
