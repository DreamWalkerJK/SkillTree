# 本机互操作（Native Interop）

> 版本信息：P/Invoke、COM 和 Marshal 自 .NET 1.0；C# 9/.NET 5 引入函数指针语法；LibraryImport 源生成器于 .NET 7 引入。本文使用 .NET 10 / C# 14，目标框架为 `net10.0`。`LibraryImport` 示例需要启用 `AllowUnsafeBlocks`。

本机互操作让托管代码调用 C/C++、操作系统 API 或 COM 组件。调用两侧必须明确调用约定、字符集、结构布局、所有权和线程模型。

## 基础 P/Invoke

~~~csharp
using System.Runtime.InteropServices;

internal static partial class NativeMethods
{
    // LibraryImport 生成的封送代码可能使用指针；项目文件需设置
    // <AllowUnsafeBlocks>true</AllowUnsafeBlocks>。
    [LibraryImport("kernel32", SetLastError = true)]
    [return: MarshalAs(UnmanagedType.Bool)]
    internal static partial bool Beep(uint frequency, uint duration);
}

bool success = NativeMethods.Beep(800, 100);
~~~

LibraryImport 需要 partial 方法和源生成器，适用于 .NET 7+；若项目仍支持旧目标框架，可使用 DllImport。库名应按平台提供条件编译或使用 OperatingSystem.IsWindows 等检查。

## 字符串与结构体

~~~csharp
using System.Runtime.InteropServices;

[StructLayout(LayoutKind.Sequential, CharSet = CharSet.Unicode)]
public struct NativePoint
{
    public int X;
    public int Y;
}

internal static partial class NativeMethods
{
    [LibraryImport("example", EntryPoint = "get_name",
        StringMarshalling = StringMarshalling.Utf8)]
    internal static partial nint GetName();
}
~~~

不要把 nint 当作托管字符串直接转换；使用 PtrToStringUTF8 或明确长度的 Span。结构体中的 bool、数组和指针需要 MarshalAs/固定布局，任何 ABI 不匹配都可能破坏栈。

## SafeHandle 与回调

~~~csharp
public sealed partial class NativeHandle : SafeHandle
{
    public NativeHandle() : base(nint.Zero, ownsHandle: true) { }
    public override bool IsInvalid => handle == nint.Zero;
    protected override bool ReleaseHandle() => NativeClose(handle);
    [LibraryImport("example")]
    [return: MarshalAs(UnmanagedType.Bool)]
    private static partial bool NativeClose(nint handle);
}
~~~

回调委托必须在本机调用期间保持 GC.KeepAlive 引用；本机异步保存回调时，把委托放到字段并在注销后释放。跨线程回调不要直接触碰 UI 对象。

## COM 和平台差异

COM 接口要求正确的 apartment（STA/MTA）和 Release 语义；优先使用生成的 interop 程序集。Windows-only API 通过 SupportedOSPlatform 注解标记，运行时用 OperatingSystem 检查。Linux/macOS 库名和符号可能不同，使用 RuntimeInformation 构建映射。

## 高级实践

- 将所有 P/Invoke 放在单独 NativeMethods 文件，提供安全托管封装。
- 对外部长度和返回码逐项验证，SetLastError 后立即读取 Marshal.GetLastWin32Error。
- 发布前在 x86/x64/arm64 和每个目标 OS 上做 ABI 测试。
- NativeAOT 中优先 LibraryImport、函数指针和 blittable 结构，避免运行时反射封送。

## 工程示例：使用 SafeHandle 封装句柄

本机 API 返回的句柄必须明确所有权。托管封装应把关闭操作集中在 SafeHandle 中，业务对象只负责调用并在释放时转交所有权。

~~~csharp
using Microsoft.Win32.SafeHandles;
using System.Runtime.InteropServices;

sealed class FileHandle() : SafeHandleZeroOrMinusOneIsInvalid(true)
{
    [DllImport("kernel32", SetLastError = true)]
    private static extern bool CloseHandle(IntPtr handle);

    protected override bool ReleaseHandle() => CloseHandle(handle);
}

public static partial class NativeFile
{
    [LibraryImport("kernel32", SetLastError = true,
        StringMarshalling = StringMarshalling.Utf16)]
    private static partial FileHandle CreateFileW(
        string name, uint access, uint share, IntPtr security,
        uint creation, uint flags, IntPtr template);
}
~~~

结构体封送时要明确字符集、对齐、固定长度数组和调用约定。跨平台代码应按 RID 分离本机实现，并在 Windows、Linux、x64、arm64 的 CI 中验证 ABI，而不是只在开发机上运行一次。

`CreateFileW` 是 Windows API，`W` 后缀表示 UTF-16 字符串；`LibraryImport` 不会根据名称推断字符编码，因此要显式设置 `StringMarshalling.Utf16`。返回的句柄由 `SafeHandle` 持有，使用完成后调用 `Dispose`，而不是再次手工调用 `CloseHandle`。
