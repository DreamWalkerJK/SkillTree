# 并行编程

> 版本信息：Task Parallel Library（TPL）于 .NET 4.0；`Parallel.ForEachAsync` 于 .NET 6；`Vector<T>` 于 .NET Framework 4.6/.NET Core 1.0；`System.Runtime.Intrinsics` 硬件内在函数于 .NET Core 3.0 提供。本文示例使用 C# 12、目标框架 `net8.0`，可迁移到 .NET 10；.NET 11 Preview 需按目标 SDK 验证。

并行把可分割的 CPU 工作分配到多个核心。I/O 并发与 CPU 并行不同；对 I/O 任务应使用 `async`/`await`，不要直接套用 `Parallel`。

## 基础用法：Parallel.For 与 ForEachAsync

~~~csharp
Parallel.For(0, data.Length,
    new ParallelOptions { MaxDegreeOfParallelism = Environment.ProcessorCount },
    i => data[i] = Transform(data[i]));

await Parallel.ForEachAsync(
    urls,
    new ParallelOptions
    {
        MaxDegreeOfParallelism = 8,
        CancellationToken = token
    },
    async (url, ct) =>
    {
        await DownloadAndStoreAsync(url, ct);
    });
~~~

循环体应尽量无共享状态。需要聚合时使用线程局部累加器或线程安全集合，避免每次迭代加锁。

~~~csharp
long total = 0;
Parallel.ForEach(
    values,
    () => 0L,
    (value, _, local) => local + value,
    local => Interlocked.Add(ref total, local));
~~~

## 高级用法：PLINQ

AsParallel 将 IEnumerable 转为并行查询；AsOrdered 保留顺序但会降低性能。只有数据量足够大、单项计算足够重时才可能获益：

~~~csharp
int[] result = values.AsParallel()
    .WithDegreeOfParallelism(4)
    .Where(IsExpensive)
    .Select(Transform)
    .ToArray();
~~~

PLINQ 查询中的委托必须线程安全、无副作用；异常会包装为 AggregateException。对数据库 IQueryable 不要直接 AsParallel，先让数据库完成可翻译查询。

## 分区与数据竞争

Parallel.ForEach 可接受 Partitioner<T> 自定义分区；Channel<T> 适合生产者/消费者。volatile 只保证可见性，不保证复合读改写原子性；计数器使用 Interlocked。

## 调优方法

- 先基准测试串行版本，再比较并行版本的吞吐和尾延迟。
- MaxDegreeOfParallelism 不必等于逻辑核心数；考虑 GC、I/O 和其他服务负载。
- 小任务会被调度开销吞噬，可批量处理或使用 SIMD。
- 通过 CancellationToken 快速停止；在 finally 中释放每个分区拥有的资源。
