# 异步编程模型：TAP、APM 与 EAP

> 版本信息：APM（Begin/End）于 .NET 1.0；EAP（事件异步模式）在 .NET 2.0/3.5 广泛使用；TAP（Task-based Asynchronous Pattern）于 .NET 4.0，C# 5 的 `async`/`await` 于 2012 年普及。示例目标为 `net10.0`、C# 14。现代 .NET 应优先使用 TAP。

异步编程模型描述 API 如何表示未完成操作、结果、取消和错误。理解历史模型有助于维护旧代码和编写兼容适配器。

## 基础用法：APM、EAP 与 TAP

### APM：Begin/End

APM 返回 IAsyncResult，调用 BeginXxx 启动、EndXxx 获取结果。End 必须调用一次以观察异常并释放资源。

~~~csharp
static Task<int> ReadLegacyAsync(Stream stream, byte[] buffer)
    => Task.Factory.FromAsync(
        stream.BeginRead, stream.EndRead, buffer, 0, buffer.Length, null);
~~~

实际适配时要确保传给 Begin 和 End 的缓冲区一致；优先寻找框架提供的 ReadAsync 重载，避免自己包装。

## EAP：事件模式

EAP 使用 XxxAsync 方法和 XxxCompleted 事件，取消通常通过 CancelAsync。事件订阅容易产生生命周期和竞态问题；适配为 TaskCompletionSource 时要处理重复完成、取消和异常。

~~~csharp
static Task<string> ToTaskAsync(LegacyClient client)
{
    var tcs = new TaskCompletionSource<string>(
        TaskCreationOptions.RunContinuationsAsynchronously);

    void Handler(object? sender, CompletedEventArgs e)
    {
        client.Completed -= Handler;
        if (e.Error is not null) tcs.TrySetException(e.Error);
        else if (e.Cancelled) tcs.TrySetCanceled();
        else tcs.TrySetResult(e.Result);
    }

    client.Completed += Handler;
    client.StartAsync();
    return tcs.Task;
}
~~~

## TAP 设计约定

- 方法名以 Async 结尾，返回 Task/Task<T>/ValueTask<T>。
- 取消令牌放在参数末尾，取消时抛 OperationCanceledException。
- 异常通过任务传播，不在后台线程静默抛出。
- 不要在库中强制 ConfigureAwait(true/false) 影响调用方策略；可在内部使用 ConfigureAwait(false)。

## 高级用法：IValueTaskSource 与自定义调度

极低分配场景可实现 IValueTaskSource<T>，复用 ManualResetValueTaskSourceCore<T>；这要求严格遵守“一次等待、版本号、并发完成”契约。除非基准数据证明收益，否则使用 Task 或 ValueTask 更可靠。

AsyncMethodBuilder 可用于自定义任务类型，但属于高级运行时扩展，需考虑调试器、异常和分析器支持。线程池、ExecutionContext 和 SynchronizationContext 的交互见相关专题。

## 迁移策略

给旧 APM/EAP API 编写一次性适配层，在适配层统一取消和异常语义；业务代码只依赖 TAP。逐步替换同步阻塞调用，删除 .Result/.Wait，并为取消、超时和重复调用增加测试。

## 适配旧式 Begin/End API

APM API 没有直接的 `CancellationToken` 参数，适配器至少要保证回调只完成一次，并在等待者取消时停止等待。取消等待不一定能终止底层本机操作，因此文档应明确说明资源何时真正释放。

~~~csharp
static async Task<int> ReadAsync(Stream stream, Memory<byte> buffer,
    CancellationToken token)
{
    // APM 只接受 byte[]；临时数组中的数据必须在等待完成后复制回调用方的 Memory。
    byte[] temporary = new byte[buffer.Length];
    int count = await Task.Factory.FromAsync(
        (callback, state) => stream.BeginRead(temporary, 0,
            temporary.Length, callback, state),
        stream.EndRead,
        state: null).WaitAsync(token);
    temporary.AsMemory(0, count).CopyTo(buffer);
    return count;
}
~~~

实际适配时应优先使用框架已经提供的 `ReadAsync`、`Socket.ReceiveAsync` 等 TAP API；`FromAsync` 主要用于维护旧组件。不要在适配器内部捕获所有异常后返回 `-1`，否则调用方无法区分取消、连接关闭和真正的 I/O 故障。

## API 设计检查表

TAP 方法通常以 `Async` 结尾，返回 `Task` 或 `Task<T>`，并把 `CancellationToken` 放在参数末尾。同步快速路径可以返回已完成任务，但不要为了省一次分配而让调用方面对难以组合的自定义状态机。

~~~csharp
public interface IBlobStore
{
    Task<Stream> OpenReadAsync(
        string key,
        CancellationToken cancellationToken = default);

    Task PutAsync(
        string key,
        Stream content,
        CancellationToken cancellationToken = default);
}
~~~

实现层应说明流的所有权：`OpenReadAsync` 返回的流由调用方释放，`PutAsync` 是否关闭传入流必须写入契约。异常类型应保留底层故障信息，取消应传播 `OperationCanceledException`，不要把取消包装成普通业务错误。
