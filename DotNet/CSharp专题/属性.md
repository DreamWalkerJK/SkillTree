# 属性（Properties 与 Attributes）

> 版本信息：.NET 10（C# 14）。属性访问器和 Attribute 语法自 C# 1.0/.NET 1.0 可用；`CallerArgumentExpression` 于 C# 10/.NET 6；泛型 Attribute 于 C# 11/.NET 7。示例目标为 `net10.0`。

C# 的 Property 通常译为“属性”，通过 `obj.Name` 这样的成员访问语法读写数据；Attribute 通常译为“特性”，通过 `[Obsolete]` 这样的声明附加元数据，再由编译器、框架或反射读取。二者不是同一种机制。

## 基础用法：属性访问器

~~~csharp
public sealed class Account
{
    private decimal _balance;

    public string Id { get; init; } = "";
    public decimal Balance
    {
        get => _balance;
        private set
        {
            if (value < 0) throw new ArgumentOutOfRangeException(nameof(value));
            _balance = value;
        }
    }

    public void Deposit(decimal amount)
    {
        if (amount <= 0) throw new ArgumentOutOfRangeException(nameof(amount));
        Balance += amount;
    }
}
~~~

init 访问器（C# 9/.NET 5）只允许对象初始化阶段赋值；required 成员（C# 11/.NET 7）要求调用方提供值。索引器使用 this[...] 暴露键值访问。

## 自定义 Attribute

~~~csharp
[AttributeUsage(AttributeTargets.Method, AllowMultiple = true)]
public sealed class AuditAttribute(string action) : Attribute
{
    public string Action { get; } = action;
}

public static class OrderCommands
{
    [Audit("create")]
    public static void CreateOrder() { }
}
~~~

Attribute 参数必须是编译期常量、Type、枚举或这些类型的数组。读取元数据：

~~~csharp
var attributes = typeof(Service).GetMethod(nameof(Service.Run))!
    .GetCustomAttributes<AuditAttribute>();
~~~

## 高级用法

CallerArgumentExpression（C# 10）可捕获传入表达式文本，适合参数验证：

~~~csharp
public static void Requires(
    bool condition,
    [System.Runtime.CompilerServices.CallerArgumentExpression(nameof(condition))]
    string? expression = null)
{
    if (!condition)
        throw new ArgumentException("条件不满足：" + expression);
}
~~~

泛型 Attribute（C# 11）减少 Type 参数的强制转换：

~~~csharp
public sealed class HandlerAttribute<T> : Attribute where T : class { }
[HandlerAttribute<OrderHandler>]
public sealed class OrderEndpoint { }
~~~

属性计算逻辑应保持快速且无副作用；需要异步加载时改用方法。Attribute 只是描述，不能承担依赖注入或复杂运行时状态。

## 工程示例：选项验证与元数据读取

配置属性可以配合 `IValidateOptions<T>` 在应用启动时验证。Attribute 适合表达字段元数据，真正的跨字段规则仍应放在验证器中。

~~~csharp
public sealed class StorageOptions
{
    [Required]
    public required string ConnectionString { get; init; }

    [Range(1, 1024)]
    public int BatchSize { get; init; } = 64;
}

public sealed class StorageOptionsValidator
    : IValidateOptions<StorageOptions>
{
    public ValidateOptionsResult Validate(string? name, StorageOptions options)
        => string.IsNullOrWhiteSpace(options.ConnectionString)
            ? ValidateOptionsResult.Fail("ConnectionString 不能为空")
            : options.BatchSize <= 0
                ? ValidateOptionsResult.Fail("BatchSize 必须大于零")
                : ValidateOptionsResult.Success;
}
~~~

使用反射读取 Attribute 时应缓存 `PropertyInfo` 和属性实例，避免在每个请求重复扫描程序集。Trim 或 NativeAOT 发布还需要为动态读取的成员声明保留信息，稳定字段优先采用源生成器。

### 选项注册、绑定与测试（.NET 10）

仅声明 `IValidateOptions<T>` 并不会自动执行验证，必须把验证器注册到容器，并在绑定时打开数据注解或 `ValidateOnStart`。`BatchSize` 的上下限应在同一处保持一致，避免配置文件通过一个入口、代码通过另一个入口得到不同结果。

~~~csharp
using System.ComponentModel.DataAnnotations;
using Microsoft.Extensions.Options;

public sealed class StorageOptions
{
    [Required, MinLength(1)]
    public required string ConnectionString { get; init; }

    [Range(1, 1024)]
    public int BatchSize { get; init; } = 64;
}

public sealed class StorageOptionsValidator : IValidateOptions<StorageOptions>
{
    public ValidateOptionsResult Validate(string? name, StorageOptions options)
    {
        if (string.IsNullOrWhiteSpace(options.ConnectionString))
            return ValidateOptionsResult.Fail("ConnectionString 不能为空");
        if (options.BatchSize is < 1 or > 1024)
            return ValidateOptionsResult.Fail("BatchSize 必须在 1 到 1024 之间");
        return ValidateOptionsResult.Success;
    }
}

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddOptions<StorageOptions>()
    .Bind(builder.Configuration.GetSection("Storage"))
    .ValidateDataAnnotations()
    .ValidateOnStart();
builder.Services.AddSingleton<IValidateOptions<StorageOptions>, StorageOptionsValidator>();
~~~

在单元测试中直接调用验证器，可以覆盖空连接字符串、0、1025 以及合法值。生产环境应避免把连接字符串原文写入异常或日志，只记录配置项名称。

~~~csharp
[Fact]
public void BatchSize_must_be_within_range()
{
    var validator = new StorageOptionsValidator();
    var result = validator.Validate(null, new StorageOptions
    {
        ConnectionString = "Server=db",
        BatchSize = 1025
    });

    Assert.Equal(ValidateOptionsResult.Fail("BatchSize 必须在 1 到 1024 之间"), result);
}
~~~

`required` 只在编译期约束对象初始化，并不能替代运行时配置验证；反序列化、环境变量和旧版调用方仍可能提供空值。对跨字段规则（例如最小批量必须小于缓存容量），实现 `IValidateOptions<T>` 比在属性 setter 中读取其他属性更容易维护。

### 属性访问器的可见性与序列化

`private set`、`init` 和只读自动属性会影响序列化器选择。System.Text.Json 默认使用公共 getter，反序列化需要可写 setter、构造函数参数或 `[JsonInclude]`。不要为了让序列化通过而把内部状态改成公共可写属性，可使用专用 DTO 或带 `[JsonConstructor]` 的构造函数。

~~~csharp
public sealed class UserSnapshot
{
    public int Id { get; }
    public string Name { get; }

    [System.Text.Json.Serialization.JsonConstructor]
    public UserSnapshot(int id, string name)
    {
        Id = id;
        Name = string.IsNullOrWhiteSpace(name)
            ? throw new ArgumentException("名称不能为空", nameof(name))
            : name;
    }
}
~~~

属性 getter 中不要执行数据库查询、记录日志或修改共享状态。调试器、序列化器和模板引擎都可能多次读取 getter；有副作用的操作应改为显式方法。
