# 线程处理

> 版本信息：Thread、Monitor、Mutex、Semaphore 自 .NET 1.0；ThreadPool 和 Timer 同期可用；Task/线程池调度于 .NET 4.0；IAsyncResult 时代的 API 仍存在但新代码应采用 TAP。示例目标为 `net8.0`，可迁移到 .NET 10；.NET 11 Preview 需按目标 SDK 验证。

线程是执行资源，Task 是工作抽象。服务器代码通常把工作排入线程池，而不是手动创建大量 Thread。

## 基础用法：Thread 与 ThreadPool

~~~csharp
Thread thread = new(() =>
{
    Console.WriteLine("专用线程：" + Environment.CurrentManagedThreadId);
});
thread.IsBackground = true;
thread.Start();
thread.Join();
~~~

Thread 适合长时间阻塞、需要独立栈或特定优先级的工作；短任务使用 Task.Run 或 ThreadPool.QueueUserWorkItem：

~~~csharp
ThreadPool.QueueUserWorkItem(static state =>
{
    Console.WriteLine(state);
}, "pool work");
~~~

不要在 ASP.NET Core 请求中用 Thread.Sleep；阻塞线程会消耗线程池。I/O 使用真正的异步 API。

## 同步原语

lock 语句（C# 13/.NET 9 对 Lock 类型有优化）保护短临界区；.NET 8 及以前可锁定私有 object。Monitor.TryEnter 可带超时，SemaphoreSlim 可用于异步等待。

~~~csharp
public sealed class Counter
{
    private readonly object _gate = new();
    private int _count;

    public void Increment()
    {
        lock (_gate)
            _count++;
    }

    private readonly SemaphoreSlim _semaphore = new(4, 4);

    public async Task UseResourceAsync(
        Func<Task> operation, CancellationToken token)
    {
        await _semaphore.WaitAsync(token);
        try { await operation(); }
        finally { _semaphore.Release(); }
    }
}
~~~

Interlocked 对单个整数、指针和引用提供原子操作；它不能替代多字段不变量的锁。

## 线程本地与取消

ThreadLocal<T> 或 AsyncLocal<T> 分别适用于线程本地和异步调用上下文。不要把请求级数据放入 ThreadStatic，因为线程会复用。CancellationToken 是协作式取消，取消回调应快速、无阻塞。

## 高级问题

锁顺序不一致会造成死锁；尽量使用单一锁、排序后的锁顺序或不可变数据。使用 Monitor、Mutex 时异常路径必须释放。并发集合（ConcurrentDictionary、Channel<T>）比手写锁更容易验证，但仍需理解复合操作的原子性。

线程池饥饿可通过 dotnet-counters 观察线程数、队列长度和请求延迟。提高 ThreadPool 最小线程数只能缓解启动突发，不能修复长期阻塞或锁竞争。

## 工程示例：有界工作队列

后台任务适合使用 `Channel<T>` 将请求接收和执行解耦。容量设置成有限值后，生产者会在过载时等待，内存不会随着请求量无限增长。

~~~csharp
using System.Threading.Channels;

var queue = Channel.CreateBounded<int>(new BoundedChannelOptions(256)
{
    FullMode = BoundedChannelFullMode.Wait,
    SingleReader = true,
    SingleWriter = false
});

async Task ProduceAsync(IEnumerable<int> ids, CancellationToken token)
{
    try
    {
        foreach (var id in ids)
            await queue.Writer.WriteAsync(id, token);
    }
    finally { queue.Writer.TryComplete(); }
}

async Task ConsumeAsync(CancellationToken token)
{
    await foreach (var id in queue.Reader.ReadAllAsync(token))
        await ProcessAsync(id, token);
}

static Task ProcessAsync(int id, CancellationToken token) => Task.CompletedTask;
~~~

关闭流程必须先停止生产者，再等待消费者排空队列；如果消费者失败，应通过 `TryComplete(exception)` 将错误传播给等待方，并把未处理项目交给持久化队列或补偿任务。
