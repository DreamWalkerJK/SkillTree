# 源生成器（Source Generators）

> 版本信息：Roslyn 传统源生成器（`ISourceGenerator`）随 C# 9/.NET 5 SDK 提供；增量源生成器（`IIncrementalGenerator`）于 C# 10/.NET 6 引入。System.Text.Json 的生成模式于 .NET 6 引入并在 .NET 8 扩展。示例宿主目标为 `net8.0`，可迁移到 .NET 10；.NET 11 Preview 的编译器行为需按具体 SDK 验证。

源生成器在编译期间读取语法树、符号和附加文件，生成参与同一编译的 C# 源码。它不能修改用户源文件，也不能在运行时执行。生成代码可减少反射、提升启动速度并改善裁剪兼容性。

## 基础：增量生成器

生成器项目应引用 Microsoft.CodeAnalysis.CSharp，并以 Roslyn analyzer 形式被消费。以下是核心结构（简化示例）：

~~~csharp
using Microsoft.CodeAnalysis;

[Generator]
public sealed class GreetingGenerator : IIncrementalGenerator
{
    public void Initialize(IncrementalGeneratorInitializationContext context)
    {
        IncrementalValueProvider<string> names =
            context.AnalyzerConfigOptionsProvider
                .Select((options, _) =>
                    options.GlobalOptions.TryGetValue(
                        "build_property.RootNamespace", out string? value)
                        ? value : "Generated");

        context.RegisterSourceOutput(names, static (spc, ns) =>
        {
            string source = "namespace " + ns +
                "; public static class Greeting { public static string Text => \"Hi\"; }";
            spc.AddSource("Greeting.g.cs", source);
        });
    }
}
~~~

实际项目应使用 SyntaxProvider 过滤候选语法，再转换为不可变的模型。增量管道必须保持纯函数、可比较输入，避免每次编译都重新扫描整个项目。

## 使用生成的代码

在应用项目中添加 analyzer 项目引用，并启用 EmitCompilerGeneratedFiles 以调试生成结果：

~~~xml
<PropertyGroup>
  <EmitCompilerGeneratedFiles>true</EmitCompilerGeneratedFiles>
  <CompilerGeneratedFilesOutputPath>$(BaseIntermediateOutputPath)generated</CompilerGeneratedFilesOutputPath>
</PropertyGroup>
~~~

System.Text.Json 示例：

~~~csharp
using System.Text.Json;
using System.Text.Json.Serialization;

[JsonSourceGenerationOptions(WriteIndented = true)]
[JsonSerializable(typeof(User))]
internal partial class AppJsonContext : JsonSerializerContext { }

string json = JsonSerializer.Serialize(
    new User(1, "Ada"), AppJsonContext.Default.User);
~~~

## 高级设计

- 用属性或命名约定作为明确输入，生成器只生成可预测的 API。
- 对诊断使用 DiagnosticDescriptor，给出位置、ID 和修复建议。
- 生成的符号名称必须包含命名空间并处理关键字、嵌套类型和泛型。
- 使用 AdditionalFiles 读取模板或协议文件，避免依赖当前工作目录。
- 生成器不得执行网络请求或读取任意文件；这会破坏可重复构建和安全审计。

增量生成器适合序列化上下文、日志模板、DI 注册、RPC 合同和正则表达式。Regex source generation（C# 11/.NET 7）示例：

~~~csharp
public static partial class NameValidation
{
    [System.Text.RegularExpressions.GeneratedRegex(
        @"^[A-Z][a-z]+$", RegexOptions.CultureInvariant)]
    public static partial System.Text.RegularExpressions.Regex NameRegex();
}
~~~

在 NativeAOT/Trim 发布中，优先使用生成模式，并在 CI 中检查生成器输出是否稳定。
