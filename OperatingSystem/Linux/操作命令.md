# Linux 常用命令与运维手册

本文面向 Linux 日常使用、开发环境维护和生产故障排查，重点说明命令的语义、适用范围、风险边界与验证方式。它不是对 `man` 手册的替代；遇到版本差异时，应以本机帮助和发行版文档为准。

> **说明**
> 示例主要面向使用 Bash、GNU coreutils、iproute2、procps-ng、util-linux 和 systemd 的常见 GNU/Linux 发行版。Alpine/BusyBox、容器、WSL、传统 SysV init、OpenRC 以及 BSD/macOS 同名命令可能缺少部分选项或具有不同语义。

> **警告**
> 删除、覆盖、递归改权限、分区、格式化、文件系统修复、防火墙和 SSH 配置变更都可能造成数据丢失或远程失联。生产环境应先确认目标与影响范围，备份配置，保留现有会话或带外恢复通道，再执行一个可验证、可回滚的变更。

## 1. 阅读约定与命令地图

### 1.1 示例约定

- 代码块不包含 `$` 或 `#` 提示符，便于复制；普通操作默认不使用 `root`。
- 全大写名称（如 `USER_NAME`、`PID`、`PORT`、`INTERFACE`、`SERVICE_NAME`）以及 `/path/to/file`、`/dev/DEVICE` 均为占位符，执行前必须替换。
- 公网示例使用 `example.com` 和文档专用地址 `192.0.2.0/24`、`198.51.100.0/24`、`203.0.113.0/24`。
- `[内建]` 表示 Shell 内建命令；`[可选]` 表示通常需要额外安装；`[systemd]` 表示仅适用于 systemd 环境。
- “只读检查”不会主动修改目标状态，但读取日志、抓包或遍历大目录仍可能带来性能与数据合规影响。

命令通常遵循以下形式：

```text
command [OPTIONS] [OPERANDS]
```

短选项经常可以合并，例如 `ls -lah`；长选项通常写作 `--human-readable`。这只是常见约定，不是所有命令都遵守。不要根据经验猜测高风险命令的参数，应先查看本机帮助。

## 2. 获取帮助与识别运行环境

### 2.1 确认发行版、内核、Shell 与 init

不要只根据目录结构或包管理器猜测环境。先建立基线：

```bash
cat /etc/os-release
uname -srmo
printf 'login shell: %s\n' "$SHELL"
ps -p 1 -o pid=,comm=,args=
```

- `/etc/os-release` 描述用户空间发行版；`uname` 描述当前运行的内核。容器内二者可能来自不同层次。
- `$SHELL` 通常是账户的登录 Shell，不一定是当前正在执行脚本的 Shell。脚本可查看 `$0`，Bash 中还可查看 `$BASH_VERSION`。
- PID 1 为 `systemd` 才能直接套用本文的完整 `systemctl` 工作流；容器中 PID 1 可能只是应用进程。

### 2.2 帮助系统

| 命令 | 用途 | 示例 |
| --- | --- | --- |
| `man` | 查看手册页 | `man rsync`、`man 5 passwd` |
| `info` | 查看 GNU Info 文档 | `info coreutils 'cp invocation'` |
| `help` | 查看 Bash 内建命令 | `help cd`、`help test` |
| `command --help` | 查看命令摘要 | `find --help` |
| `whatis` | 查询手册页的一行说明 | `whatis chmod` |
| `apropos` | 按关键词搜索手册页 | `apropos 'copy files'` |
| `type -a` | 显示命令解析结果及所有候选 | `type -a printf` |
| `command -v` | 以适合脚本的方式判断命令是否可用 | `command -v systemctl` |
| `whereis` | 查找程序、源码和手册的大致位置 | `whereis ssh` |

`which` 往往是外部程序，可能无法准确反映 alias、函数和 Shell 内建命令；交互排查优先使用 `type -a`，脚本判断优先使用 `command -v`。

常见 `man` 章节：

| 章节 | 内容 | 示例 |
| --- | --- | --- |
| 1 | 用户命令 | `man 1 passwd` |
| 2 | 系统调用 | `man 2 open` |
| 3 | 库函数 | `man 3 printf` |
| 4 | 设备与特殊文件 | `man 4 null` |
| 5 | 文件格式与配置 | `man 5 passwd`、`man 5 fstab` |
| 7 | 约定、协议与概览 | `man 7 signal`、`man 7 ip` |
| 8 | 系统管理命令 | `man 8 mount` |

同名条目有歧义时必须指定章节，例如 `passwd(1)` 是修改密码的命令，`passwd(5)` 是 `/etc/passwd` 文件格式。

## 3. Shell 基础语义

### 3.1 退出状态与条件执行

Linux 命令通常以 `0` 表示成功，以非零值表示失败或特殊结果；具体含义由命令定义。

```bash
command
printf 'exit status=%s\n' "$?"

build_command && deploy_command
primary_command || fallback_command
```

- `$?` 只保存最近一个前台管道的状态，执行其他命令后就会被覆盖。
- `cmd1 && cmd2` 仅在 `cmd1` 成功时运行 `cmd2`；`cmd1 || cmd2` 仅在 `cmd1` 非零时运行 `cmd2`。
- 不要把 `cmd1 && cmd2 || cmd3` 当成严格的 `if/else`：如果 `cmd2` 失败，`cmd3` 也会执行。
- 一些命令使用非零值表达“有差异”或“有可用更新”，例如 `grep` 未匹配返回 `1`，`diff` 发现差异返回 `1`，`dnf check-upgrade` 发现更新通常返回 `100`。自动化必须按命令语义判断。

Bash/常见 Shell 中经常看到以下状态，但具体命令仍可能自行定义：

| 状态 | 常见含义 |
| ---: | --- |
| `0` | 成功 |
| `1` | 一般失败，或布尔“假/未匹配” |
| `2` | 用法/参数错误，部分 Shell 也用于语法错误 |
| `126` | 找到命令但不能执行 |
| `127` | 找不到命令 |
| `128+N` | 进程因编号 N 的信号退出的常见编码 |
| `130` | 常见于 SIGINT（`Ctrl-c`）终止 |

退出状态范围通常只有 8 位，脚本应使用 `0..255`，并为自己的状态建立稳定、文档化的含义。

### 3.2 引号、展开与通配符

| 写法 | 语义 |
| --- | --- |
| `'text $HOME'` | 单引号内保持字面值，不能直接包含单引号 |
| `"text $HOME"` | 双引号内执行变量和命令替换，但抑制分词与路径名展开 |
| `\$HOME` | 反斜杠转义下一个字符 |
| `$(command)` | 命令替换，优先于旧式反引号 |
| `*`、`?`、`[abc]` | Shell 路径名通配，不是正则表达式 |
| `{a,b}`、`{1..5}` | Bash 花括号展开，发生在路径名展开之前 |

变量通常应加双引号：

```bash
file_path='/tmp/report with spaces.txt'
printf '%s\n' "$file_path"
cp -- "$file_path" /safe/target/
```

`*` 默认不匹配以 `.` 开头的名称，并且无匹配时在 Bash 默认设置下可能原样传给命令。不要使用 `for f in $(find ...)` 处理文件名；空格、换行和通配字符都会破坏边界。

### 3.3 管道与重定向

| 写法 | 作用 |
| --- | --- |
| `cmd >file` | 标准输出覆盖写入文件 |
| `cmd >>file` | 标准输出追加到文件 |
| `cmd 2>file` | 标准错误覆盖写入文件 |
| `cmd >file 2>&1` | 标准输出和标准错误都进入文件 |
| `cmd 2>&1 \| tee file` | 合并输出后显示并写入文件 |
| `cmd <file` | 从文件读取标准输入 |
| `cmd1 \| cmd2` | 将 `cmd1` 标准输出连接到 `cmd2` 标准输入 |
| `cmd &` | 在当前 Shell 中启动后台作业 |

重定向按从左到右的顺序处理，下面两条并不等价：

```bash
command >combined.log 2>&1
command 2>&1 >stdout.log
```

第二条先让标准错误指向原来的标准输出，再单独重定向标准输出，因此错误通常仍出现在终端。

`sudo` 只提升它所执行的程序，重定向仍由当前 Shell 完成。下面的写法通常无法写入仅 root 可写的文件：

```bash
sudo printf '%s\n' 'value' > /etc/example.conf
```

编辑现有系统配置优先使用 `sudoedit`；确实需要把标准输入写入特权文件时，可明确使用 `tee`：

```bash
printf '%s\n' 'value' | sudo tee /etc/example.conf >/dev/null
```

在 Bash 脚本中，管道默认返回最后一个命令的状态。需要让管道中任一环节失败都被感知时，可使用：

```bash
set -o pipefail
producer | consumer
```

### 3.4 环境变量、PATH 与命令缓存

```bash
env
printenv PATH
export APP_ENV=production
unset APP_ENV
printf '%s\n' "$PATH" | tr ':' '\n'
```

- Shell 变量只有经过 `export` 才会传给子进程。
- `PATH` 从左到右搜索；空元素可能代表当前目录，不应出现在高权限账户的安全配置中。
- 当前目录默认不在 `PATH`，运行其中的程序应显式写 `./program`。
- Bash 可能缓存命令路径；安装或替换程序后可用 `hash -r` 清除缓存。
- `sudo` 通常按自身策略重置环境与 `PATH`，不要假设用户环境会完整继承。

临时为单个命令设置环境变量：

```bash
LC_ALL=C command
https_proxy=http://127.0.0.1:8080 curl https://example.com/
```

环境变量可能被子进程、诊断工具或日志读取，不适合长期承载高价值 Secret。

### 3.5 命令历史与终端快捷键

```bash
history
history 20
fc -l -10
```

常见 Readline 快捷键：

| 按键 | 作用 |
| --- | --- |
| `Ctrl-a` / `Ctrl-e` | 跳到行首 / 行尾 |
| `Alt-b` / `Alt-f` | 按单词向左 / 向右移动 |
| `Ctrl-u` / `Ctrl-k` | 删除光标前 / 后内容 |
| `Ctrl-w` | 删除前一个单词 |
| `Ctrl-r` | 反向搜索历史 |
| `Ctrl-c` | 向前台进程组发送中断信号 |
| `Ctrl-z` | 暂停前台作业，之后可用 `fg`/`bg` |
| `Ctrl-d` | 发送 EOF；空命令行中通常退出 Shell |

不要把密码、Token 或私钥内容直接写在命令行中；它们可能进入历史、审计日志或进程参数。可在当前 Shell 中用前置空格忽略历史的行为依赖 `HISTCONTROL=ignorespace`，不能当作可靠保密机制。

### 3.6 安全处理特殊文件名

文件名可能以 `-` 开头或包含空格、制表符甚至换行。常用防护方式：

```bash
rm -- -unexpected-name
cp -- "$source_path" "$target_path"
find /path -type f -print0 | xargs -0 file
```

- `--` 告诉支持该约定的命令停止解析选项。
- 机器处理任意文件名时优先使用 NUL 分隔：`find -print0`、`xargs -0`、`sort -z` 等。
- 不要解析 `ls` 的展示输出；脚本应使用 `find`、glob、`stat` 或专用接口。

### 3.7 alias、source、watch 与持久终端

```bash
alias
alias ll='ls -lah'
unalias ll
source ~/.bashrc
```

- alias 主要服务交互 Shell，默认不会在非交互 Bash 脚本中展开；脚本应使用函数或直接写完整命令。
- `source FILE`（POSIX 写法为 `. FILE`）在当前 Shell 中执行文件，能修改当前变量、函数和目录。只 source 可信、已审查的文件。
- 修改 `~/.bashrc` 后 source 可让当前会话重新读取，但重复加载是否安全取决于配置是否幂等。

重复观察状态：

```bash
watch -n 2 --differences 'ss -s'
```

`watch` 通常每 2 秒运行一次命令；引号决定是当前 Shell 还是 watch 启动的 Shell 解释特殊字符。高频运行昂贵查询会加重故障，应按成本设置间隔，按 `Ctrl-c` 停止。

终端显示异常时：

```bash
clear
reset
```

`clear` 只清屏；`reset` 会重新初始化终端状态，适合二进制输出破坏回显后恢复，但不会修复远程连接或应用状态。

长时间交互维护可使用 tmux `[可选]`：

```bash
tmux new-session -s maintenance
tmux list-sessions
tmux attach-session -t maintenance
```

默认按 `Ctrl-b` 再按 `d` 可分离会话。tmux 能抵抗普通 SSH 断线，但不是服务管理器；会话内命令、滚动缓冲和凭据仍需按敏感数据保护。`screen` 是另一种常见终端复用器，键位和会话模型不同。

## 4. 系统、会话与时间信息

### 4.1 常用只读检查

```bash
cat /etc/os-release
uname -a
hostnamectl
uptime
date --iso-8601=seconds
timedatectl
locale
id
who
w
last -n 10
```

| 命令 | 说明 |
| --- | --- |
| `uname -r` | 当前内核版本 |
| `hostnamectl` | 主机名、虚拟化与操作系统摘要；需要 systemd 相关组件 |
| `uptime` | 运行时长、登录用户数和 1/5/15 分钟 load average |
| `date` | 显示或格式化系统时间；修改时间通常需要特权 |
| `timedatectl` | 时区、NTP 同步与 RTC 状态 `[systemd]` |
| `locale` | 当前语言、字符集和排序规则 |
| `whoami` | 当前有效用户名 |
| `id` | UID、主 GID、补充组和安全上下文信息 |
| `who` / `w` | 登录会话；`w` 还显示进程与负载摘要 |
| `last` / `lastb` | 登录历史 / 失败登录历史；数据取决于日志保留，`lastb` 常需 root |
| `tty` | 当前标准输入关联的终端 |
| `stty -a` | 终端行规程设置 |

load average 不是 CPU 使用率。Linux 中它大致反映可运行任务和不可中断睡眠任务数量；高负载可能来自 CPU 饱和，也可能来自 I/O 堵塞。

### 4.2 时间、时区与本地化

```bash
date '+%F %T %z'
date -u '+%FT%TZ'
timedatectl status
timedatectl list-timezones | grep 'Asia/'
locale charmap
```

修改时区示例：

```bash
sudo timedatectl set-timezone Asia/Shanghai
```

时间变更会影响证书校验、分布式系统、日志关联和定时任务。生产环境应使用经过批准的 NTP/时间同步方案，不要在未评估的情况下手工跳变时钟。

## 5. 文件系统导航与文件操作

### 5.1 路径与目录导航

| 命令 | 说明 |
| --- | --- |
| `pwd -P` | 显示解析符号链接后的物理工作目录 |
| `cd /path` | 切换目录 `[内建]` |
| `cd -` | 返回上一个目录 |
| `cd` 或 `cd ~` | 返回当前用户家目录 |
| `pushd` / `popd` / `dirs` | 管理 Bash 目录栈 |
| `ls -lah` | 包含隐藏项、长格式、人类可读大小 |
| `ls -ld DIR` | 查看目录本身，而不是列出目录内容 |
| `tree -a -L 2` | 树形展示两层目录 `[可选]` |

路径规则：

- `/` 开头的是绝对路径；其他路径相对于当前工作目录。
- `.` 表示当前目录，`..` 表示父目录，`~USER_NAME` 表示指定用户家目录。
- 多个 `/` 通常等价于一个，但路径的大小写敏感性由文件系统决定。
- 目录项名称不等于文件对象本身；硬链接可让多个目录项指向同一 inode。

`ls -l` 第一列的首字符表示对象类型：`-` 普通文件、`d` 目录、`l` 符号链接、`b` 块设备、`c` 字符设备、`p` FIFO、`s` Unix socket。

### 5.2 创建文件和目录

```bash
touch file.txt
mkdir directory
mkdir -p /path/to/nested/directory
mktemp
mktemp -d
```

- `touch` 在文件不存在时创建空文件；存在时默认更新时间戳，不会清空内容。
- `mkdir -p` 创建缺失的父目录，已存在时通常不报错。
- 临时文件和目录应使用 `mktemp`，避免可预测名称带来的竞态条件和符号链接攻击。

### 5.3 查看类型与元数据

```bash
file /path/to/file
stat /path/to/file
stat -c '%n %F %s bytes %a %U:%G %y' /path/to/file
namei -l /path/to/file
```

- `file` 根据内容特征判断类型，不只看扩展名。
- `stat` 显示 inode、大小、块数、权限、属主和时间戳。GNU `stat -c` 与 BSD `stat -f` 语法不同。
- `namei -l` 展开路径每一级并显示权限，排查“文件权限看似正确但仍 Permission denied”时很有用。
- 常见时间包括 `mtime`（内容修改）、`ctime`（inode 状态改变）和 `atime`（访问）；Linux 常规文件系统通常不保存可移植的“创建时间”。

### 5.4 复制、移动和安装文件

```bash
cp source.txt destination.txt
cp -i source.txt destination.txt
cp -a source_directory/ destination_directory/
mv -i old_name new_name
install -D -m 0755 app /usr/local/bin/app
install -D -m 0644 app.conf /etc/app/app.conf
```

| 选项 | 说明 |
| --- | --- |
| `cp -i` / `mv -i` | 覆盖前询问；交互行为不适合无人值守脚本 |
| `cp -n` / `mv -n` | 尽量不覆盖现有目标；具体冲突语义应查本机帮助 |
| `cp -r` | 递归复制目录 |
| `cp -a` | GNU 归档模式，尽量保留权限、属主、时间、链接与扩展属性等 |
| `cp --reflink=auto` | 文件系统支持时尝试写时复制 `[GNU]` |
| `install` | 一步完成复制、建父目录、设置模式/属主，适合部署单个文件 |

关键语义：

- `target/` 已存在且是目录时，`cp -a source/ target/` 会得到 `target/source/...`；`target` 不存在时，它本身会成为 `source` 的副本。`cp -a source/. target/` 复制的是 `source` 的内容，包括隐藏项。
- 同一文件系统内的 `mv` 通常只是重命名目录项，近似原子；跨文件系统移动会退化为复制后删除，失败语义不同。
- 覆盖重要配置前先创建带时间戳或受版本控制的备份，并使用 `diff` 验证。
- alias（例如把 `cp` 设为 `cp -i`）不应成为脚本安全性的前提。

### 5.5 删除文件和空目录

```bash
rmdir empty_directory
rm -i file.txt
rm -- -unexpected-name
```

> **谨慎操作**
> `rm` 通常不会进入回收站。`rm -r` 会递归删除，`rm -f` 会减少确认与报错；两者组合在变量为空、路径拼错或权限过高时尤其危险。本文不提供可直接复制的宽泛递归强制删除示例。

删除前的安全流程：

```bash
find /var/log/myapp -xdev -type f -name '*.log' -mtime +30 -print
```

先审查输出、确认挂载边界与保留策略，再把明确的匹配集合交给删除流程。还应注意：

- 删除或重命名目录项主要取决于父目录的写权限和执行权限，不取决于文件本身是否可写。
- 正在被进程打开的文件删除后，目录项会消失，但磁盘块要等最后一个文件描述符关闭才释放。
- `find -delete` 会直接修改数据，并隐含深度优先语义；使用前必须先以相同条件执行 `-print`。
- shell glob 展开失败、隐藏文件、跨文件系统和符号链接都可能让实际范围偏离直觉。

### 5.6 硬链接与符号链接

```bash
ln existing_file hard_link
ln -s /absolute/target symbolic_link
ln -sfn /new/target current
readlink symbolic_link
readlink -f symbolic_link
realpath /path/with/links
```

| 特性 | 硬链接 | 符号链接 |
| --- | --- | --- |
| 指向对象 | 同一 inode | 保存另一条路径 |
| 跨文件系统 | 不支持 | 支持 |
| 链接目录 | 普通用户通常不允许 | 支持 |
| 目标删除后 | 只要仍有硬链接，数据仍在 | 变为悬空链接 |
| 权限显示 | 与同一 inode 共享 | 访问时通常检查目标；链接本身权限意义有限 |

发布版本常用“新目录 + 原子切换符号链接”的方式，但 `ln -sfn` 在目标是既有真实目录等情况下仍需谨慎验证。使用 `readlink` 或 `realpath` 检查最终指向。

### 5.7 路径拆分和定位

```bash
basename /var/log/nginx/access.log
dirname /var/log/nginx/access.log
realpath ./relative/path
readlink -e /path/that/must/exist
```

- `basename` 和 `dirname` 做字符串级路径处理，不负责验证目标存在。
- `realpath`/`readlink` 的选项在精简环境中可能不同。
- 脚本中处理自身目录时，要同时考虑符号链接、相对调用和当前目录变化；没有一个简短写法能覆盖所有可移植场景。

### 5.8 使用 find 精确查找

基本结构：

```text
find START_PATH [TESTS] [ACTIONS]
```

常用示例：

```bash
find /etc -type f -name '*.conf' -print
find /var/log -xdev -type f -size +100M -printf '%s %p\n' | sort -n
find /srv/app -type f -mtime -1 -print
find /path -type f -user USER_NAME -print
find /path -type f \( -name '*.log' -o -name '*.txt' \) -print
find /path -type f -exec stat -- '{}' +
find /path -type f -exec sha256sum -- '{}' +
```

| 条件/动作 | 说明 |
| --- | --- |
| `-type f/d/l` | 普通文件 / 目录 / 符号链接 |
| `-name` / `-iname` | 区分 / 不区分大小写的 glob 匹配 |
| `-mtime +N/-N` | 按整天粒度匹配修改时间；边界并非直观的精确小时数 |
| `-mmin +N/-N` | 按分钟粒度匹配修改时间 |
| `-size +100M` | GNU find 中 `M` 为 1024² 字节单位并按单位向上取整 |
| `-xdev` | 不跨越其他文件系统 |
| `-maxdepth N` | 限制递归深度 `[GNU/部分实现]` |
| `-exec cmd '{}' \;` | 每个匹配执行一次命令 |
| `-exec cmd '{}' +` | 批量传参，更高效且保留文件名边界 |
| `-print0` | 以 NUL 分隔输出，适合任意文件名 |

`find` 中隐式与运算优先于 `-o`，组合条件应显式加转义括号。默认不会跟随符号链接；`-L` 会改变遍历和判断语义，可能造成循环或跨越意外边界。

### 5.9 locate 与可选的目录树工具

```bash
locate nginx.conf
locate -i '/readme.md'
tree -a -L 3 /etc/systemd
```

- `locate` 查询定期更新的数据库，速度快但结果可能陈旧；数据库通常由 `updatedb` 更新。
- `tree` 常需额外安装，适合展示，不适合作为机器可解析接口。

## 6. 查看、搜索与处理文本

### 6.1 查看文件内容

| 命令 | 典型用法 | 说明 |
| --- | --- | --- |
| `cat` | `cat file` | 顺序输出文件；不适合交互浏览超大文件 |
| `tac` | `tac file` | 逆序输出行 `[GNU]` |
| `nl` | `nl -ba file` | 为所有行编号 |
| `less` | `less file` | 分页浏览，支持搜索和跟踪 |
| `head` | `head -n 20 file` | 查看前 20 行 |
| `tail` | `tail -n 50 file` | 查看后 50 行 |
| `tail -F` | `tail -F app.log` | 按名称重试跟踪，更适合日志轮转 `[GNU]` |
| `wc` | `wc -l file` | 统计行数；`-w` 单词数，`-c` 字节数，`-m` 字符数 |

`less` 常用按键：

| 按键 | 作用 |
| --- | --- |
| `Space` / `b` | 下一页 / 上一页 |
| `g` / `G` | 文件开头 / 结尾 |
| `/pattern` / `?pattern` | 向下 / 向上搜索 |
| `n` / `N` | 下一个 / 上一个匹配 |
| `F` | 持续跟踪增长内容，按 `Ctrl-c` 返回普通浏览 |
| `q` | 退出 |

`tail -f` 跟随已打开的文件描述符；日志被重命名并新建后，它可能继续盯住旧文件。GNU `tail -F` 等价于按文件名重试的跟踪，更适合常见日志轮转，但仍不能替代日志系统的检索能力。

### 6.2 grep：按行搜索

```bash
grep -n -- 'ERROR' app.log
grep -F -- 'literal.text[1]' app.log
grep -E -- 'timeout|connection refused' app.log
grep -RIn --exclude-dir=.git -- 'pattern' /path/to/source
grep -C 3 -- 'request-id-123' app.log
```

| 选项 | 说明 |
| --- | --- |
| `-F` | 固定字符串，不解释正则表达式 |
| `-E` | 扩展正则表达式 |
| `-i` | 忽略大小写；结果受 locale 影响 |
| `-n` | 显示行号 |
| `-r` / `-R` | 递归；对符号链接的处理存在差别，应查本机手册 |
| `-A/-B/-C N` | 显示匹配后的、前的、前后各 N 行 |
| `-l` / `-L` | 只列出有匹配 / 无匹配的文件名 |
| `-v` | 反向选择未匹配行 |
| `-q` | 静默，只用退出状态表达是否匹配 |

`grep` 常见退出状态为：`0` 找到匹配，`1` 没有匹配，`2` 发生错误。脚本不能把 `1` 与读取失败混为一谈。`grep -P` 使用 PCRE，是 GNU grep 的可选能力，不属于 POSIX，也并非所有构建都支持。

扩展正则表达式常用元素：

| 表达式 | 含义 |
| --- | --- |
| `^` / `$` | 行首 / 行尾 |
| `.` | 任意单个字符 |
| `[abc]` / `[^abc]` | 字符集合 / 排除集合 |
| `*` / `+` / `?` | 前一项重复 0 次以上 / 1 次以上 / 0 或 1 次 |
| `{m,n}` | 重复 m 到 n 次 |
| `(a\|b)` | 分组与二选一 `[ERE]` |

Shell glob 和正则是两套语法。`find -name '*.log'` 中引号防止 Shell 先展开 glob；`grep -E '.*\.log$'` 中则由 grep 解释正则。

大型代码仓库中可使用 ripgrep `[可选]`：

```bash
rg -n -F 'literal text' /path/to/repository
rg --files -g '*.service'
```

`rg` 默认尊重 `.gitignore` 并跳过隐藏文件和二进制文件，与 `grep -R` 的默认范围不同。

### 6.3 sed：流式替换与筛选

```bash
sed -n '20,40p' file.txt
sed -n '/BEGIN/,/END/p' file.txt
sed 's/old/new/' file.txt
sed 's/old/new/g' file.txt
sed -E '/^[[:space:]]*(#|$)/d' config.conf
```

- 默认把处理结果写到标准输出，不会修改原文件。
- `s/old/new/` 每行只替换第一个匹配；末尾 `g` 表示替换该行全部匹配。
- 地址 `20,40` 限定行范围；`-n` 配合 `p` 只输出选中内容。
- 分隔符不必是 `/`，处理路径时可写 `sed 's#/old/path#/new/path#g'`，减少转义。

原地修改的实现存在可移植性差异。GNU sed 可用以下方式同时保留备份：

```bash
sed -i.bak 's/old/new/g' file.txt
diff -u file.txt.bak file.txt
```

BSD/macOS `sed -i` 的参数规则不同。重要配置更稳妥的流程是写到临时文件、验证内容与语法，再以正确权限原子替换。

### 6.4 awk：按记录和字段处理

```bash
awk -F: '{ print $1, $7 }' /etc/passwd
awk '$9 >= 500 { count[$9]++ } END { for (code in count) print code, count[code] }' access.log
awk 'BEGIN { total=0 } { total += $1 } END { print total }' numbers.txt
```

awk 默认一行一个记录，以连续空白分字段：`$0` 为整行，`$1` 为第一个字段，`NF` 为当前字段数，`NR` 为累计记录号。`-F:` 设置输入分隔符；输出分隔符可在 `BEGIN` 中设置 `OFS`。

不要用简单的 `-F,` 解析允许引号、转义和嵌入换行的完整 CSV；这类数据应使用真正的 CSV 解析器。

### 6.5 排序、去重与字段组合

```bash
sort file.txt
sort -n numbers.txt
sort -t: -k3,3n /etc/passwd
sort names.txt | uniq
sort access.log | uniq -c | sort -nr
cut -d: -f1,7 /etc/passwd
paste -d, names.txt values.txt
tr '[:lower:]' '[:upper:]' < input.txt
```

| 命令 | 要点 |
| --- | --- |
| `sort` | 默认按 locale 排序；确定性脚本常临时设置 `LC_ALL=C` |
| `uniq` | 只合并相邻重复行，因此常先 `sort`；`-c` 计数，`-d` 只显示重复项 |
| `cut` | 按字符或单一分隔符取字段，不是通用 CSV/JSON 解析器 |
| `paste` | 按行合并文件 |
| `tr` | 单字符转换、删除或压缩重复，例如 `tr -s '[:space:]' ' '` |
| `join` | 按键连接两个已排序文本文件 |
| `comm` | 比较两个已排序文件的独有行和共有行 |
| `column` | 对齐列或按分隔符排版 `[util-linux/可选]` |

`join`、`comm` 与前置 `sort` 必须使用一致的 locale 和键规则，否则会出现缺失或顺序错误。

### 6.6 tee、xargs 与安全管道

```bash
command 2>&1 | tee command.log
printf '%s\0' file1 'file with spaces' | xargs -0 file
find /path -type f -name '*.tmp' -exec stat -- '{}' +
```

- `tee` 同时写标准输出和文件；`tee -a` 追加。写特权文件时应明确审查输入来源。
- `xargs` 把标准输入转换为命令参数，默认按空白和引号规则切分，不能安全承载任意文件名。
- `find -print0 | xargs -0` 或 `find -exec ... {} +` 能保持文件名边界。
- GNU `xargs -r` 在空输入时不运行命令，但它不是 POSIX 选项；若副作用敏感，优先使用 `find -exec` 或显式判断输入。
- 并行 `xargs -P` 可能打乱输出，并放大 CPU、I/O、API 或数据库压力。

### 6.7 diff、分割、编码与二进制观察

```bash
diff -u old.conf new.conf
cmp file1.bin file2.bin
split -b 1G image.bin image.part.
file --mime file.txt
iconv -f GB18030 -t UTF-8 input.txt > output.txt
od -An -tx1 -N64 file.bin
xxd -l 64 file.bin
strings -n 8 executable | less
```

| 命令 | 说明 |
| --- | --- |
| `diff -u` | 生成统一格式文本差异；返回 1 通常表示有差异，不是执行错误 |
| `cmp` | 按字节比较文件，适合二进制 |
| `split` / `csplit` | 按大小/行数或上下文切分文件 |
| `iconv` | 转换字符编码；转换前应确认源编码并保留原文件 |
| `od` | POSIX 风格的字节/数值转储 |
| `xxd` | 十六进制查看和反向转换 `[常随 Vim 安装]` |
| `strings` | 从二进制提取可打印片段，不能证明文件安全或完整 |

应用统一 diff 补丁前先预览：

```bash
patch --dry-run -p1 < change.patch
patch --backup -p1 < change.patch
```

`-p1` 去掉路径的第一层，是否正确取决于补丁头。补丁会修改工作树，且可能包含越界路径或覆盖敏感文件；应在版本控制/隔离副本中审查目标列表，确认 dry-run 后再应用。

JSON 建议使用专用解析器 `jq` `[可选]`：

```bash
jq -r '.items[] | [.name, .status] | @tsv' response.json
curl --fail-with-body --silent --show-error https://example.com/api | jq .
```

`jq -r` 输出原始字符串而不是 JSON 引号。YAML 可使用 `yq`，但不同同名实现的语法差异很大，自动化中应锁定具体项目和版本。

## 7. vi 与 Vim 编辑器

### 7.1 vi、Vim 与模式

`vi` 是传统 Unix 编辑器接口；系统中的 `vi` 可能由 Vim、nvi、BusyBox vi 等实现提供。Vim（Vi IMproved）扩展了可视模式、文本对象、分屏、标签页、持久撤销和插件等能力。Vim 可通过 `vim --version` 或编辑器内的 `:version` 确认特性；通用 `vi` 不保证支持 `--version`，应结合 `type -a vi`、符号链接、alternatives/包数据库和该实现自己的帮助确认。

Vim 的核心是“模式化编辑”：

| 模式 | 用途 | 进入方式 |
| --- | --- | --- |
| 普通模式 | 移动、删除、复制、粘贴和组合操作 | 启动后默认；其他模式按 `Esc` 返回 |
| 插入模式 | 输入文本 | `i`、`a`、`o` 等 |
| 命令行模式 | 保存、退出、替换和设置 | 普通模式按 `:`、`/` 或 `?` |
| 可视模式 `[Vim]` | 选择字符、行或矩形区域 | `v`、`V`、`Ctrl-v` |

如果不确定当前模式，按一次 `Esc` 回到普通模式，再输入命令。

### 7.2 30 秒生存指南

```bash
vi /path/to/file
```

| 目标 | 操作 |
| --- | --- |
| 开始输入 | 按 `i` |
| 返回普通模式 | 按 `Esc` |
| 保存 | 输入 `:w` 后回车 |
| 退出 | 输入 `:q` 后回车 |
| 保存并退出 | `:x` 或 `:wq` |
| 丢弃当前缓冲区修改并退出 | `:q!` |
| 撤销 | `u` |
| 搜索 | `/pattern`，回车后用 `n`/`N` 跳转 |
| 跳到第 120 行 | `:120` 或 `120G` |

`:x` 只在缓冲区发生修改时写盘；`:wq` 会执行写入后退出。两者通常结果相同，但可能影响文件修改时间等元数据。

### 7.3 启动与恢复

```bash
vim file.txt
vim +120 file.txt
vim +/pattern file.txt
vim -R file.txt
vim -d old.conf new.conf
vim -r file.txt
```

| 用法 | 说明 |
| --- | --- |
| `vim +120 file` | 打开并跳到第 120 行 |
| `vim +/pattern file` | 打开并跳到第一个匹配 |
| `vim -R file` / `view file` | 只读意图打开；拥有权限时仍可能强制写入 |
| `vim -d a b` / `vimdiff a b` | 差异模式 `[Vim]` |
| `vim -r file` | 尝试从交换文件恢复 `[Vim]` |

遇到 E325 交换文件警告时，先检查提示中的 PID、主机名和文件时间，确认是否仍有另一个编辑进程。需要时用 `vim -r FILE` 恢复并另存、比较；不要未经确认直接删除交换文件，否则可能覆盖他人的有效编辑或丢失恢复数据。

### 7.4 移动光标

| 按键 | 作用 |
| --- | --- |
| `h`、`j`、`k`、`l` | 左、下、上、右 |
| `w`、`b`、`e` | 下一个单词首、上一个单词首、当前/下一个单词尾 |
| `W`、`B`、`E` | 按空白分隔的 WORD 移动 `[Vim/常见 vi]` |
| `0`、`^`、`$` | 物理行首、首个非空白、行尾 |
| `fX` / `tX` | 移到本行下一个字符 X / 其前一位；`;`、`,` 重复/反向 |
| `%` | 在成对括号等结构间跳转 |
| `gg` / `G` | 文件开头 `[Vim]` / 文件结尾 |
| `120G` | 跳到第 120 行 |
| `Ctrl-f` / `Ctrl-b` | 向前 / 向后翻页 |
| `Ctrl-d` / `Ctrl-u` | 向下 / 向上滚动半页 |
| `H`、`M`、`L` | 当前窗口顶部、中部、底部 |
| `{` / `}` | 上一个 / 下一个段落 |

大多数移动可加计数，例如 `5j` 下移 5 行、`3w` 向前移动 3 个单词。

### 7.5 插入、删除、修改、复制与粘贴

进入插入模式：

| 按键 | 作用 |
| --- | --- |
| `i` / `a` | 在光标前 / 后插入 |
| `I` / `A` | 在行首首个非空白 / 行尾插入 |
| `o` / `O` | 在下方 / 上方新建一行 |
| `R` | 进入覆盖模式 |

常用编辑：

| 按键 | 作用 |
| --- | --- |
| `x` / `X` | 删除当前 / 前一个字符 |
| `rX` | 用字符 X 替换当前字符，完成后仍处于普通模式 |
| `dd` | 删除当前行 |
| `D` | 删除到行尾，近似 `d$` |
| `cc` | 修改当前行 |
| `C` | 修改到行尾，近似 `c$` |
| `yy` / `Y` | 复制当前行 |
| `p` / `P` | 在光标后/下方或前/上方粘贴 |
| `J` | 连接下一行 |
| `u` | 撤销最近修改 |
| `Ctrl-r` | 重做 `[Vim]` |
| `.` | 重复最近一次修改 |

vi/Vim 的关键语法是“操作符 + 移动/文本对象 + 可选计数”：

```text
d w      删除到下一个单词边界
d $      删除到行尾
c i w    修改当前单词 [Vim 文本对象]
c i "    修改双引号内部 [Vim 文本对象]
y 3 w    复制后续三个单词
3 d d    删除三行
```

常用操作符：`d` 删除、`c` 修改、`y` 复制、`>` 增加缩进、`<` 减少缩进、`=` 自动缩进 `[Vim]`。常用 Vim 文本对象由 `i`（inside）或 `a`（around）加对象组成，例如 `iw`、`aw`、`i"`、`a)`、`ip`。

### 7.6 寄存器与系统剪贴板

删除和复制内容会进入寄存器。Vim 常用操作：

```text
"ayy     复制当前行到命名寄存器 a
"ap      粘贴寄存器 a
"_dd     删除当前行但丢入黑洞寄存器，不覆盖常用寄存器
"+yy     复制当前行到系统剪贴板；可视选择后使用 "+y
"+p      从系统剪贴板粘贴
:registers
```

系统剪贴板寄存器 `+` 仅在 Vim 构建包含 `+clipboard`，并且图形/显示环境可用时生效。可用 `:version` 或 `vim --version | grep clipboard` 检查。

### 7.7 搜索与替换

| 操作 | 命令 |
| --- | --- |
| 向下 / 向上搜索 | `/pattern` / `?pattern` |
| 下一个 / 上一个匹配 | `n` / `N` |
| 搜索光标下单词 | `*` / `#` `[Vim]` |
| 关闭当前搜索高亮 | `:nohlsearch` `[Vim]` |
| 当前行替换第一个 | `:s/old/new/` |
| 当前行替换全部 | `:s/old/new/g` |

`%` 表示整个文件范围，末尾 `g` 表示每行全部匹配，`c` 表示逐项确认。Vim 搜索默认使用自身正则语法，与 grep ERE/PCRE 不完全相同。替换包含 `/` 的路径时可换分隔符：


```vim

```

`smartcase` 通常与 `ignorecase` 配合：模式含大写字母时恢复大小写敏感。

### 7.8 Ex 范围命令

```vim
:10,20p
:10,20d
:g/DEBUG/p
:g/DEBUG/d
:v/^[[:space:]]*#/d
:sort
:read /path/to/snippet.txt

```

- `:g/pattern/command` 对所有匹配行执行命令；`:v` 对不匹配行执行。
- `:sort` 是 Vim 扩展，不是所有传统 vi/Ex 实现都支持。
- `:read !command`、`:write !command` 和 `:!command` 会启动外部命令，其权限等同于编辑器进程，处理不可信内容时要谨慎。
- 删除大量行前可先把命令结尾的 `d` 改为 `p` 预览范围，或保存副本后再操作。

### 7.9 缓冲区、窗口和标签页 `[Vim]`

三个概念不要混淆：缓冲区是已载入内存的文件内容；窗口是缓冲区的视图；标签页是窗口布局的集合。

```vim
:edit other.conf
:write
:write /tmp/copy.conf
:saveas new-name.conf
:ls
:bnext
:bprevious
:buffer 3
:bdelete
:split other.conf
:vsplit other.conf
:tabnew other.conf
```

| 操作 | 按键/命令 |
| --- | --- |
| 窗口间移动 | `Ctrl-w h/j/k/l` 或 `Ctrl-w w` |
| 关闭当前窗口 | `:close` |
| 只保留当前窗口 | `:only` |
| 下/上一个标签页 | `gt` / `gT` |
| 列出缓冲区 | `:ls` 或 `:buffers` |
| 切换到备用文件 | `Ctrl-^` |

`:bdelete` 删除缓冲区，不一定退出 Vim；`:quit` 关闭窗口，当最后一个窗口关闭时才退出程序。

### 7.11 配置、编码与换行

Vim 用户配置通常位于 `~/.vimrc`，Neovim 通常位于 `~/.config/nvim/init.vim` 或 `init.lua`。一个保守起点：

## 8. 归档、压缩、分割与完整性校验

### 8.1 归档与压缩的区别

归档把多个目录项及其元数据组织成一个流；压缩减少字节体积。`tar` 负责归档，并可调用 gzip、bzip2、xz 或 zstd 等压缩器。

```bash
tar -cf archive.tar directory/
tar -czf archive.tar.gz directory/
tar -cJf archive.tar.xz directory/
tar --zstd -cf archive.tar.zst directory/
tar -tvf archive.tar.gz
tar -xzf archive.tar.gz -C /safe/target
```

常用操作字母：`c` 创建、`t` 列表、`x` 提取、`f` 指定归档文件、`v` 显示详情；压缩字母 `z` 为 gzip、`j` 为 bzip2、`J` 为 xz。`f` 后紧跟的参数是归档文件名，使用分离的长选项更不易混淆。

> **谨慎操作**
> 解压不可信归档前先用 `tar -tvf` 查看成员类型、权限、名称和符号链接目标，检查绝对路径、`..` 路径与异常目标，并解压到新建的隔离目录。列表审查不能替代低权限隔离提取；以 root 提取时恢复属主、权限和特殊文件的风险更高，不要直接覆盖生产目录。

从指定目录创建归档可避免把本机绝对路径或多余父目录写入：

```bash
tar -C /srv/app -czf app-config.tar.gz config/
```

`tar` 归档是文件级备份，不自动保证运行中数据库、虚拟机镜像或频繁变化目录的一致性。应使用应用提供的快照/导出机制，并测试恢复流程。

### 8.2 单文件压缩工具

```bash
gzip -k large.log
gunzip -c large.log.gz > large.restored.log
zcat large.log.gz | less

xz -k image.raw
unxz -c image.raw.xz > image.restored.raw

zstd -k backup.tar
unzstd -c backup.tar.zst > backup.restored.tar
```

| 工具 | 常见特点 |
| --- | --- |
| `gzip` | 兼容性广、速度和压缩率均衡 |
| `bzip2` | 旧环境常见，通常比 gzip 慢 |
| `xz` | 压缩率高，压缩较慢且可能消耗较多内存 |
| `zstd` | 现代环境中速度与压缩率平衡较好，可能需额外安装 |
| `zip`/`unzip` | 跨平台文件交换常见，Unix 元数据保真度需验证 |

以上压缩和解压命令是独立示例；解压使用标准输出写入不同名称，避免因 `-k` 保留的原文件已存在而覆盖失败。xz 的 `-T0` 会使用所有可用线程，并可能显著放大内存占用；资源受限主机应省略它或设置经过容量评估的线程数。

压缩炸弹会在解压时占用极大空间或资源。处理不可信文件前应检查大小、配额和隔离环境。

### 8.3 ZIP 文件

```bash
zip -r archive.zip directory/
unzip -l archive.zip
unzip archive.zip -d /safe/target
```

命令行密码保护的传统 Zip 加密不适合高安全性需求，而且密码可能进入历史或进程参数。敏感备份应使用经过评估的现代加密格式和密钥管理方案。

### 8.4 分割与合并大文件

```bash
split -b 1G -d image.iso image.iso.part-
cat image.iso.part-* > image.reassembled.iso
```

合并后必须校验摘要；glob 排序只有在分片命名宽度一致时可靠。GNU `split` 可用 `-a` 调整后缀长度。

### 8.5 摘要与完整性验证

```bash
sha256sum image.iso
sha256sum -c SHA256SUMS
b2sum archive.tar.zst
```

- 摘要只能在“可信来源提供了预期值”时验证完整性；与文件放在同一不可信来源的裸摘要不能证明发布者身份。
- 发布物优先验证数字签名或受信任渠道中的摘要。
- MD5 和 SHA-1 可用于非对抗性的偶然损坏检测或兼容场景，但不应作为抵抗恶意篡改/碰撞的安全校验。
- 校验读取整个文件，会带来相应 I/O；对生产大盘应评估影响。

## 9. 用户、组、权限、ACL 与 capabilities

### 9.1 身份与 NSS 查询

```bash
whoami
id
id USER_NAME
groups USER_NAME
getent passwd USER_NAME
getent group GROUP_NAME
getent hosts example.com
```

`/etc/passwd` 和 `/etc/group` 只包含本地数据库。企业环境还可能通过 LDAP、SSSD、NIS 或其他 NSS 模块提供账户，因此查询账户、组和主机名优先使用 `getent`。

`id` 输出中的真实 UID、有效 UID 和组决定常规 DAC 权限；容器 user namespace、SELinux/AppArmor、ACL、capabilities 和挂载选项还会施加额外限制。

### 9.2 用户和组管理

不同发行版对 `useradd` 默认值、`adduser` 封装和家目录模板的约定不同。创建前先查看本机配置与帮助：

```bash
useradd --defaults
cat /etc/shells
```

常见操作：

```bash
sudo groupadd GROUP_NAME
sudo useradd -m -s /bin/bash USER_NAME
sudo passwd USER_NAME
sudo usermod -aG GROUP_NAME USER_NAME
id USER_NAME
```

| 命令 | 说明 |
| --- | --- |
| `useradd` | 低层创建账户；默认是否建家目录因发行版而异 |
| `adduser` | Debian 等系统上的交互式高级封装；并非统一可移植接口 |
| `usermod -aG` | 追加补充组；漏掉 `-a` 会替换整个补充组列表 |
| `gpasswd -a USER GROUP` | 把用户加入组 |
| `passwd` | 设置或变更密码与部分锁定状态 |
| `chage` | 查看和管理密码有效期 |
| `userdel` / `groupdel` | 删除账户/组；可能影响文件属主与运行中的进程 |

查看密码有效期：

```bash
sudo chage -l USER_NAME
```

`passwd -l USER_NAME` 主要锁定密码凭据，不会自动撤销 SSH 公钥、Kerberos、Token、已存在会话或其他认证方式。停用账户必须根据认证体系制定完整流程。

> **谨慎操作**
> 删除账户家目录、邮件目录或递归改属主可能不可恢复。删除前应检查运行中进程、定时任务、sudoers、SSH key、文件所有权、应用凭据和审计保留要求。本文不提供无上下文的递归账户清理命令。

组成员变更通常在新登录会话中生效。`newgrp GROUP_NAME` 会启动具有新组上下文的 Shell，但不能替代对完整登录环境的验证。

### 9.3 su、sudo 与安全提权

```bash
su - USER_NAME
sudo -l
sudo command --option
sudo -iu USER_NAME
sudoedit /etc/example.conf
sudo visudo
sudo visudo -c
```

- `su - USER_NAME` 模拟目标用户登录，加载其登录环境；不带 `-` 时环境继承语义不同。
- `sudo -l` 显示当前用户被允许执行的规则；策略可能限制参数、主机、环境和目标用户。
- `sudo -iu USER_NAME` 以目标用户启动登录式 Shell，适合验证服务账户环境。
- sudoers 文件必须通过 `visudo` 编辑和校验；片段通常位于 `/etc/sudoers.d/`，文件名和权限还受发行版策略约束。
- 不要运行不理解的交互程序或编辑器作为 root；许多程序可以启动 Shell、加载插件或读取用户配置。

### 9.4 rwx 权限语义

```text
-rw-r----- 1 alice app 2048 Aug 14 10:00 config.ini
│└┬┘└┬┘└┬┘
│ │  │  └─ other
│ │  └──── group
│ └─────── user/owner
└───────── type
```

文件和目录上的权限语义不同：

| 权限 | 普通文件 | 目录 |
| --- | --- | --- |
| `r` | 读取内容 | 列出目录项名称 |
| `w` | 修改/截断内容 | 创建、删除、重命名目录项，通常还需要 `x` |
| `x` | 作为程序执行；脚本还需要有效解释器 | 遍历目录并访问已知名称 |

只有目录 `r` 没有 `x` 时，可能看见名称却无法 `stat` 内容；只有 `x` 没有 `r` 时，知道准确名称仍可能访问。删除文件主要取决于父目录权限，文件自身只读不等于不可删除。

八进制位值：`r=4`、`w=2`、`x=1`。

| 模式 | user | group | other | 常见用途 |
| --- | --- | --- | --- | --- |
| `600` | `rw-` | `---` | `---` | 私钥、仅属主可读写的 Secret |
| `640` | `rw-` | `r--` | `---` | 组可读配置 |
| `644` | `rw-` | `r--` | `r--` | 普通非敏感文本 |
| `700` | `rwx` | `---` | `---` | 私有目录/脚本 |
| `750` | `rwx` | `r-x` | `---` | 组可进入的程序目录 |
| `755` | `rwx` | `r-x` | `r-x` | 公共可遍历目录和可执行程序 |

这些只是常见值，不是万能模板。配置是否可公开读取、程序是否应可执行，应由威胁模型和服务身份决定。

### 9.5 chmod、chown 与 chgrp

```bash
chmod 640 config.ini
chmod 750 scripts/
chmod u=rw,g=r,o= config.ini
chmod g+w shared-directory/
chmod --reference=known-good.conf target.conf

chown USER_NAME:GROUP_NAME file
chgrp GROUP_NAME file
```

符号模式中的对象为 `u`（属主）、`g`（组）、`o`（其他）、`a`（全部），操作为 `+`、`-`、`=`。`chmod =` 会明确覆盖目标类别权限，通常比只追加位更易审计。

> **谨慎操作**
> 递归 `chmod`/`chown` 会穿过整个目录树，并可能破坏可执行位、服务账户边界、ACL、容器卷或共享存储语义。不要用 `chmod -R 777` 解决权限问题；先用 `namei -l`、`stat`、`getfacl`、`findmnt` 和 MAC 审计日志确认阻断层。

如果确实需要分别规范目录与文件权限，应先只读审查：

```bash
find /srv/app -xdev -printf '%M %u:%g %p\n' | less
```

再设计区分 `-type d` 与 `-type f` 的变更，并在小范围验证。`find -printf` 属于 GNU 扩展。

### 9.6 umask

```bash
umask
umask -S
umask 027
```

umask 清除程序请求权限中的相应位，不是简单十进制减法。普通文件通常最多请求 `0666`，目录通常最多请求 `0777`：

```text
请求文件模式 0666，umask 0027 → 0640
请求目录模式 0777，umask 0027 → 0750
```

程序可以主动请求更少权限；ACL 默认项也可能改变最终结果。交互 Shell 的 `umask` 不一定影响 systemd 服务，服务可通过 unit 的 `UMask=` 单独设置。

### 9.7 setuid、setgid 与 sticky bit

特殊位使用高一位八进制表示：setuid=`4xxx`、setgid=`2xxx`、sticky=`1xxx`。

| 特殊位 | 典型语义 |
| --- | --- |
| 文件 setuid | 执行时采用文件属主的有效 UID；Linux 通常忽略脚本上的 setuid |
| 文件 setgid | 执行时采用文件所属组的有效 GID |
| 目录 setgid | 新建项继承目录组，适合受控共享目录 |
| 目录 sticky | 未特权调用者通常只有在自己拥有目标目录项、自己是目录属主，或拥有相应特权时，才能删除/重命名该目录项；`/tmp` 常见 |

```bash
find / -xdev -type f -perm /6000 -print 2>/dev/null
stat -c '%A %a %U:%G %n' /tmp
```

setuid/setgid 程序会扩大攻击面，应定期盘点并与受信任基线比较。挂载选项 `nosuid`、容器和安全模块可能让这些位不生效。

### 9.8 ACL

```bash
getfacl shared/
setfacl -m u:USER_NAME:rw file
setfacl -m g:GROUP_NAME:rwx shared/
setfacl -d -m g:GROUP_NAME:rwx shared/
getfacl shared/
```

- ACL 为传统 user/group/other 之外的特定用户和组赋权。
- 目录默认 ACL（`-d`）影响新建子项，不会自动追溯修改既有内容。
- ACL mask 限制命名用户、命名组和所属组条目的最大有效权限；`getfacl` 会显示 `effective` 结果。
- 复制、归档和同步是否保留 ACL 取决于工具选项与目标文件系统。`cp -a`、`tar`、`rsync -A` 的支持仍需在本机验证。

### 9.9 扩展属性、不可变标记与 capabilities

```bash
getfattr -d file
setfattr -n user.note -v 'reviewed' file

lsattr file
sudo chattr +i file
sudo chattr -i file

getcap -r /usr/bin 2>/dev/null
getcap /path/to/program
sudo setcap 'cap_net_bind_service=+ep' /path/to/program
getcap /path/to/program
```

- `getfattr`/`setfattr` 操作扩展属性；SELinux 标签也存储在特定安全命名空间，但应通过 SELinux 工具管理。
- `chattr +i` 在支持的文件系统上设置不可变标记，会阻止常规修改、重命名和删除；它常使后续运维“看似权限正确但无法写入”。
- Linux capabilities 把部分 root 权限拆成细粒度能力。`setcap` 会替换目标文件的完整 capability 集合，变更前后都应记录精确目标的 `getcap` 输出；只授予明确需要的能力，并记录二进制升级后能力可能丢失或指向旧文件的问题。原先没有 capability 时，可把 `setcap -r FILE` 作为受控回滚；若原先已有能力，应恢复记录的完整原值。
- 不要通过给解释器、通用 Shell 或可加载任意代码的程序授予高风险 capability 来绕过服务权限设计。

### 9.10 Permission denied 排查顺序

```bash
id
namei -l /path/to/file
stat /path/to/file
getfacl /path/to/file
findmnt -T /path/to/file -o TARGET,SOURCE,FSTYPE,OPTIONS
lsattr /path/to/file
```

然后检查：

1. 进程的实际 UID/GID 与补充组，而不只是登录用户名。
2. 每一级目录的 `x` 权限、目标文件权限和父目录写权限。
3. ACL mask 与默认 ACL。
4. 文件系统是否只读，是否有 `noexec`、`nosuid` 等挂载限制。
5. SELinux/AppArmor 拒绝日志与标签。
6. 容器 user namespace、只读根文件系统和 capability 限制。

## 10. 软件包管理

### 10.1 发行版矩阵

| 发行版系列 | 高级管理器 | 低层查询/包格式 | 常见 init/差异 |
| --- | --- | --- | --- |
| Debian / Ubuntu | `apt`、`apt-get` | `dpkg`、`.deb` | systemd；AppArmor 常见 |
| Fedora / RHEL 8+ / Rocky / Alma | `dnf` | `rpm`、`.rpm` | systemd；SELinux、firewalld 常见 |
| openSUSE | `zypper` | `rpm`、`.rpm` | systemd；AppArmor 常见 |
| Arch Linux | `pacman` | `pacman` 包数据库 | systemd；不支持部分升级 |
| Alpine | `apk` | `apk` 包数据库 | BusyBox、musl、OpenRC 常见 |

先确认 `/etc/os-release`，不要跨发行版混用仓库或照搬第三方源配置。

### 10.2 Debian / Ubuntu

```bash
sudo apt update
apt list --upgradable
apt search PACKAGE_NAME
apt show PACKAGE_NAME
apt-cache policy PACKAGE_NAME
sudo apt install PACKAGE_NAME
sudo apt remove PACKAGE_NAME
sudo apt purge PACKAGE_NAME
sudo apt upgrade
```

- `apt update` 只刷新包索引，不安装更新。
- `upgrade`、`full-upgrade` 对依赖变化和删除包的处理不同，系统大版本升级应遵循发行版专用流程。
- `apt` 面向交互使用，稳定自动化通常优先 `apt-get` 和 `apt-cache`，并显式处理退出码和非交互配置。
- `apt autoremove` 会删除被判断为不再需要的自动依赖；执行前审查列表。

查询已安装文件：

```bash
dpkg -l PACKAGE_NAME
dpkg -L PACKAGE_NAME
dpkg -S /path/to/installed/file
```

安装本地包优先让高级管理器解决依赖：

```bash
sudo apt install ./package.deb
```

### 10.3 Fedora / RHEL 系

```bash
dnf search PACKAGE_NAME
dnf info PACKAGE_NAME
dnf list --installed PACKAGE_NAME
sudo dnf install PACKAGE_NAME
sudo dnf upgrade
sudo dnf remove PACKAGE_NAME
dnf repoquery -l PACKAGE_NAME
dnf provides '/path/or/glob'
```

`dnf check-upgrade` 在存在可用更新时通常返回 `100`，自动化应把它与真实错误区分。`repoquery` 等子命令在部分版本可能来自插件包。

仍在延长支持流程中的 RHEL 7 使用 `yum`；不要把面向 RHEL 8+ 的 DNF5/DNF4 选项直接套用。此类旧环境还应依据厂商生命周期和组织升级计划处理。

RPM 低层查询：

```bash
rpm -q PACKAGE_NAME
rpm -ql PACKAGE_NAME
rpm -qf /path/to/installed/file
rpm -V PACKAGE_NAME
```

`rpm -V` 比较已安装文件与包数据库记录；配置文件被合法修改也会产生差异，不能看到输出就直接覆盖。

### 10.4 openSUSE

```bash
sudo zypper refresh
zypper search PACKAGE_NAME
zypper info PACKAGE_NAME
sudo zypper install PACKAGE_NAME
sudo zypper update
sudo zypper remove PACKAGE_NAME
zypper repos
```

滚动版与固定版的推荐升级命令可能不同，应遵循对应 openSUSE 产品文档。

### 10.5 Arch Linux

```bash
sudo pacman -Syu
pacman -Ss PACKAGE_NAME
pacman -Qi PACKAGE_NAME
pacman -Ql PACKAGE_NAME
pacman -Qo /path/to/installed/file
sudo pacman -S PACKAGE_NAME
```

Arch 不支持部分升级。不要仅刷新数据库后安装单个包而长期不升级系统（典型问题是 `pacman -Sy PACKAGE`）；日常应保持同步数据库与已安装包的一致性，并在升级前阅读官方新闻中的人工干预事项。

### 10.6 Alpine

```bash
sudo apk update
apk search PACKAGE_NAME
apk info PACKAGE_NAME
sudo apk add PACKAGE_NAME
sudo apk upgrade
sudo apk del PACKAGE_NAME
apk info -W /path/to/installed/file
```

Alpine 常使用 BusyBox `ash`、musl libc 和 OpenRC。即使命令名相同，GNU 长选项、Bash 脚本与 systemd 工作流也可能不可用。最小安装通常没有 `sudo`；状态变更命令需以 root 或经组织配置的 `doas`/`sudo` 执行，示例中的 `sudo` 应替换为本机批准的提权方式。

### 10.7 软件源与升级安全

- 优先使用发行版官方仓库或经过组织审批、带签名元数据的仓库。
- 不长期使用 `curl URL | sh`。先下载到文件，审查内容、最终 URL、签名/摘要和安装范围，再在隔离环境验证。
- 不通过关闭 TLS 校验或签名校验“修复”仓库问题。
- 包管理器锁通常表示另一个事务正在运行；先识别进程和事务状态，不要随意删除锁文件。
- 更新 libc、内核、OpenSSL、systemd 等基础组件后，磁盘上的库已更新不代表所有进程已加载新版本。应按变更计划重启相关服务或主机并验证。
- 内核包安装成功不等于当前内核已切换；用 `uname -r` 与已安装包版本对比，并确认引导与回滚项。

## 11. 进程、作业、信号与资源

### 11.1 进程模型与状态

每个进程有 PID、父 PID（PPID）、凭据、文件描述符、地址空间、线程和调度状态。`/proc/PID/` 暴露 Linux 进程视图，进程退出或 PID 被复用后内容会变化。

常见状态：

| 状态 | 含义 |
| --- | --- |
| `R` | 正在运行或可运行 |
| `S` | 可中断睡眠，通常在等待事件 |
| `D` | 不可中断睡眠，常见于 I/O 或内核等待 |
| `T` | 被作业控制或调试器停止 |
| `Z` | 僵尸：已经退出，等待父进程回收 |
| `I` | 空闲内核线程，具体显示依工具版本而异 |

僵尸已没有可执行代码，向僵尸本身发送 `SIGKILL` 无法回收它；应修复父进程的 `wait` 逻辑，必要时按服务流程重启父进程。

### 11.2 ps、pgrep 与进程树

```bash
ps -ef
ps aux
ps -eo pid,ppid,user,stat,%cpu,%mem,rss,etime,cmd --sort=-%cpu
ps -L -p PID -o pid,tid,psr,stat,%cpu,comm
pgrep -af 'nginx'
pidof nginx
pstree -ap
```

- `ps -ef` 使用 Unix 风格选项，`ps aux` 使用 BSD 风格选项；避免含糊的 `ps -aux`。
- `%CPU` 和 `%MEM` 的计算窗口、线程汇总方式与工具有关，不能替代连续采样。
- `pgrep name` 默认匹配进程名；`pgrep -f pattern` 匹配完整命令行，范围可能远大于预期。
- PID 会复用。在准备发送信号或调试前同时核对 PID、启动时间、命令行、用户和 cgroup。

查看单个进程：

```bash
tr '\0' ' ' < /proc/PID/cmdline; printf '\n'
grep -E '^(Name|State|Pid|PPid|Threads|VmRSS|VmSwap):' /proc/PID/status
readlink -f /proc/PID/exe
ls -l /proc/PID/fd | less
cat /proc/PID/cgroup
```

读取其他用户进程信息可能受权限、`hidepid`、容器命名空间或安全策略限制。

### 11.3 top、free 与连续采样

```bash
top
free -h
vmstat 1
mpstat -P ALL 1
iostat -xz 1
pidstat -dur -p ALL 1
```

`htop`、`mpstat`、`iostat`、`pidstat`、`sar`、`iotop` 通常需要额外安装；`mpstat`、`iostat`、`pidstat` 和 `sar` 常来自 `sysstat`，`htop` 与 `iotop` 分属各自软件包。

重要解释：

- `free` 应重点看 `available`，Linux 会主动利用内存做页缓存，低 `free` 不等于内存耗尽。
- RSS 包含共享页并可能在多个进程中重复计数；精确归因可结合 PSS（如 `/proc/PID/smaps_rollup`）和 cgroup 指标。
- swap 使用不等于正在发生严重换页；结合 `vmstat` 的 `si/so` 观察活动。
- `vmstat`、`iostat`、`mpstat`、`pidstat` 的第一组数据常是自启动以来或自进程启动以来的累计平均，后续采样才反映指定间隔。
- `iostat` 字段含义和设备饱和判断依内核、设备类型与版本而异；不要只凭单一 `%util` 下结论。

`top` 常用交互键：`P` 按 CPU 排序、`M` 按内存排序、`1` 展开每 CPU、`H` 切换线程、`k` 发送信号、`q` 退出。生产环境中发送信号前仍应离开交互界面核对目标。

### 11.4 信号与安全终止流程

```bash
kill -l
kill -TERM PID
kill -HUP PID
kill -KILL PID
```

| 信号 | 编号（Linux 常见） | 语义 |
| --- | ---: | --- |
| `SIGHUP` | 1 | 终端挂断；部分守护进程约定为重载配置 |
| `SIGINT` | 2 | 交互中断，常由 `Ctrl-c` 触发 |
| `SIGTERM` | 15 | 可捕获的正常终止请求；`kill PID` 默认发送它 |
| `SIGKILL` | 9 | 内核立即终止，不能捕获或清理，只作最后手段 |
| `SIGSTOP` | 19 | 强制停止，不能捕获 |
| `SIGCONT` | 18 | 继续已停止进程 |

编号除标准信号外可能因架构而异，脚本优先使用名称。建议流程：

1. 确认服务管理器是否应负责停止进程，systemd 服务优先 `systemctl stop`。
2. 记录 PID、启动时间、命令行与当前日志。
3. 发送 `SIGTERM`，等待应用规定的优雅退出时间。
4. 再次确认同一进程仍存在，分析为什么未退出。
5. 仅在业务影响大且无法正常清理时使用 `SIGKILL`，随后检查数据一致性和遗留资源。

`pkill`/`killall` 按名称或模式匹配，误伤范围比 PID 更难直观看清。先使用对应 `pgrep` 条件预览。`SIGKILL` 不会自动清理共享内存、临时文件、锁语义或子进程，也不会让应用刷新缓冲区。

### 11.5 Shell 作业控制

```bash
long_command &
jobs -l
fg %1
bg %1
```

- `jobs` 只显示当前 Shell 的作业表，不是系统进程清单。
- `Ctrl-z` 通常向前台进程组发送 `SIGTSTP`，进程停止后可用 `bg` 继续后台运行或 `fg` 拉回前台。
- 关闭终端时，Shell 和终端可能向作业发送 SIGHUP，行为受 Shell 设置、PTY 和程序处理影响。

```bash
nohup command >command.log 2>&1 &
disown %1
```

`nohup` 只调整 SIGHUP 和默认输出，不提供重启、依赖、权限隔离、资源限制、健康检查或日志轮转；长期生产进程应交给 systemd、容器编排器或适当服务管理器。

### 11.6 nice、I/O 优先级、CPU 亲和性与限制

```bash
nice -n 10 command
sudo renice -n 5 -p PID
ionice -c 2 -n 7 -p PID
taskset -pc PID
prlimit --pid PID
timeout --signal=TERM --kill-after=10s 60s command
```

- nice 值越大，普通调度策略下优先级倾向越低；降低 nice 值通常需要特权。
- `ionice` 的效果取决于 I/O 调度器、存储栈和 cgroup 配置。
- `taskset` 限制 CPU 亲和性不等于预留 CPU，错误绑定可能降低性能。
- `ulimit` 是 Shell 内建接口，影响当前 Shell 及其子进程；systemd 服务还受 unit 的 `Limit*=` 和 cgroup 限制。
- `timeout` 到期默认发送 TERM；`--kill-after` 可设置宽限期，超时退出码需查本机手册并在脚本中处理。

### 11.7 打开的文件、端口与占用者

```bash
lsof -p PID
lsof /path/to/file
lsof -iTCP:443 -sTCP:LISTEN -nP
fuser -vm /path/to/mountpoint
ss -lntup
```

`lsof` 和 `fuser` 常需额外安装或特权才能看到完整结果。`fuser -k` 会向占用进程发送信号，属于有副作用操作；单个文件先用 `fuser -v FILE`，整个挂载文件系统先用不含 `-k` 的 `fuser -vm MOUNTPOINT` 只读确认。

查找已经删除但仍占用空间的文件：

```bash
sudo lsof +L1
```

正确处理通常是让持有文件的服务按流程重新打开日志或重启，而不是直接操作 `/proc/PID/fd`。先确认文件用途、服务可用性与数据保留要求。

### 11.8 strace 与进阶诊断

```bash
strace -f -tt -T -o trace.log command
sudo strace -f -p PID -o trace.log
```

`strace` 可观察系统调用、错误码和耗时，但会增加开销、改变时序，并可能记录路径、参数和敏感数据。附加到生产进程前应获得授权并限制时间、系统调用集合与输出权限。性能分析还可使用 `perf`、eBPF 工具和应用级 profiler，但需要与内核版本和安全策略匹配。

## 12. systemd 服务与启动管理

### 12.1 unit 类型与适用范围

systemd 管理的对象称为 unit：

| 类型 | 后缀 | 用途 |
| --- | --- | --- |
| Service | `.service` | 守护进程或一次性任务 |
| Socket | `.socket` | socket 激活 |
| Timer | `.timer` | 定时激活其他 unit |
| Mount / Automount | `.mount` / `.automount` | 挂载与按需挂载 |
| Target | `.target` | unit 分组和启动状态目标 |
| Path | `.path` | 监控路径变化并触发 unit |

只有 systemd 作为系统或用户会话管理器运行时，`systemctl` 才能正常连接。容器、WSL、chroot 和 Alpine/OpenRC 环境即使命令存在，也可能出现“System has not been booted with systemd”之类错误。

### 12.2 查看 unit 状态

```bash
systemctl status SERVICE_NAME.service --no-pager
systemctl is-active SERVICE_NAME.service
systemctl is-enabled SERVICE_NAME.service
systemctl is-failed SERVICE_NAME.service
systemctl --failed
systemctl list-units --type=service --state=running
systemctl list-unit-files --type=service
```

- `status` 展示当前状态、主进程、cgroup 和最近日志，但不是完整历史。
- `is-active` 判断当前运行状态；`is-enabled` 判断是否配置为随相关 target 启动。二者相互独立。
- `list-units` 默认只列出已载入 unit；`list-unit-files` 查看安装的 unit 文件及启用状态。
- unit 名称存在发行版差异，例如 SSH 服务常见 `ssh.service` 或 `sshd.service`，cron 常见 `cron.service` 或 `crond.service`。先查询而不是猜测。

查看定义和属性：

```bash
systemctl cat SERVICE_NAME.service
systemctl show SERVICE_NAME.service -p FragmentPath -p DropInPaths -p MainPID -p ExecMainStatus
systemctl list-dependencies SERVICE_NAME.service
systemd-delta
```

### 12.3 启动、停止、重载与开机启用

```bash
sudo systemctl start SERVICE_NAME.service
sudo systemctl stop SERVICE_NAME.service
sudo systemctl restart SERVICE_NAME.service
sudo systemctl reload SERVICE_NAME.service
sudo systemctl reload-or-restart SERVICE_NAME.service

sudo systemctl enable --now SERVICE_NAME.service
sudo systemctl disable --now SERVICE_NAME.service
```

| 操作 | 准确含义 |
| --- | --- |
| `start` | 立即启动，不自动设置未来开机启动 |
| `enable` | 建立启动依赖关系，不保证立即启动；加 `--now` 才同时启动 |
| `stop` | 立即停止，不自动取消未来开机启动 |
| `disable` | 移除启用链接，不保证立即停止；加 `--now` 才同时停止 |
| `restart` | 停止后重新启动，通常会中断服务 |
| `reload` | 请求应用重载自身配置，只有 unit/程序实现时才可用 |
| `daemon-reload` | 让 systemd 重新读取 unit 定义，不会重载应用配置或自动重启服务 |

`reload-or-restart` 在支持 reload 时重载，否则重启，仍应评估服务实现和连接影响。变更前先运行应用自身的配置校验命令，例如 Nginx 的 `nginx -t` 或 OpenSSH 的 `sshd -t`。

### 12.4 disable、mask 与失败状态

```bash
sudo systemctl mask SERVICE_NAME.service
sudo systemctl unmask SERVICE_NAME.service
sudo systemctl reset-failed SERVICE_NAME.service
```

- `mask` 通常把 unit 链接到 `/dev/null`，阻止手工和依赖启动，比 `disable` 更强。
- `reset-failed` 清除失败状态和部分启动速率限制计数，不会修复根因。
- 在屏蔽系统关键 unit 前必须检查反向依赖和恢复路径。

### 12.5 使用 drop-in 覆盖配置

不要直接修改 `/usr/lib/systemd/system/` 或 `/lib/systemd/system/` 下由包管理器维护的文件。使用：

```bash
sudo systemctl edit SERVICE_NAME.service
systemctl cat SERVICE_NAME.service
sudo systemctl daemon-reload
sudo systemctl restart SERVICE_NAME.service
systemctl status SERVICE_NAME.service --no-pager
```

`systemctl edit` 默认创建 drop-in，常见路径为 `/etc/systemd/system/UNIT.d/override.conf`。例如调整服务环境和重启策略：

```ini
[Service]
Environment=APP_ENV=production
Restart=on-failure
RestartSec=5s
```

注意：

- 同名标量配置通常覆盖旧值，列表型配置的清空/追加语义依具体指令而异；查阅对应 `systemd.directives` 手册。
- `Environment=` 不适合直接存放高价值 Secret；unit 配置和 D-Bus 属性可能被有权限的用户读取。
- systemd 的 `ExecStart=` 默认不经过 Shell。systemd 支持自身的 `$VAR`/`${VAR}` 环境变量替换，且二者的参数拆分语义不同；管道、重定向、glob 和命令替换不会按 Shell 语法执行。只有确实需要 Shell 语法时才显式调用固定 Shell，并承担正确引用与注入风险；详细规则见 `systemd.service(5)`。
- 修改 unit 后先验证定义，再重启：

```bash
unit_path="$(systemctl show --value -p FragmentPath SERVICE_NAME.service)"
systemd-analyze verify "$unit_path"
systemctl cat SERVICE_NAME.service
```

`systemctl edit` 创建的是 drop-in，`/etc/systemd/system/SERVICE_NAME.service` 这个完整 fragment 往往不存在。应从 `FragmentPath` 获取实际 unit 文件，并用 `systemctl cat` 检查 fragment 与 drop-in 的合并结果；如果属性为空，先确认 unit 名称和加载状态。

drop-in 路径验证可结合 `systemctl cat` 和日志。`daemon-reload` 成功不代表应用新配置有效。

### 12.6 启动性能与依赖分析

```bash
systemd-analyze time
systemd-analyze blame
systemd-analyze critical-chain
systemctl list-dependencies --reverse SERVICE_NAME.service
```

`blame` 显示 unit 激活耗时，但并不直接代表它阻塞了启动；关键路径应看 `critical-chain`，还要考虑 socket 激活、并行启动和设备等待。

### 12.7 关机、重启与 target

```bash
sudo systemctl reboot
sudo systemctl poweroff
sudo shutdown -r +10 'Planned maintenance'
sudo shutdown -c
```

这些命令会中断所有用户和业务。执行前确认变更窗口、集群摘流、数据落盘、远程控制台、启动项和健康检查。`shutdown -c` 只能取消仍在等待的计划关机。

### 12.8 非 systemd 系统

| 环境 | 常见命令 |
| --- | --- |
| SysV 兼容层 | `service NAME status`、`service NAME restart` |
| OpenRC | `rc-service NAME status`、`rc-service NAME restart`、`rc-update show` |
| 容器 | 通常直接以前台方式运行主进程，由容器运行时/编排器管理 |

不要在非 systemd 环境机械替换命令。服务依赖、重启、日志和开机启用模型各不相同。

## 13. 日志、内核消息与审计

### 13.1 journalctl 查询

```bash
journalctl -b --no-pager
journalctl --list-boots
journalctl -b -1
journalctl -k -b
journalctl -u SERVICE_NAME.service -b
journalctl -u SERVICE_NAME.service --since '30 minutes ago'
journalctl --since '2026-08-14 09:00:00' --until '2026-08-14 10:00:00'
journalctl -p warning -b
journalctl -f
journalctl --disk-usage
```

| 选择器 | 说明 |
| --- | --- |
| `-b` / `-b -1` | 当前 / 上一次启动；前次日志必须仍被保留 |
| `-k` | 内核消息 |
| `-u UNIT` | 指定 unit，可重复使用 |
| `--since` / `--until` | 时间范围，解析受本地时区影响 |
| `-p warning` | 选择 warning 及更严重优先级 |
| `-f` | 持续跟踪新日志 |
| `-o short-iso-precise` | 使用高精度 ISO 风格时间输出 |
| `-o json-pretty` | 结构化输出，适合检查字段但体积较大 |

按字段查询：

```bash
journalctl _PID=PID
journalctl _UID=1000
journalctl SYSLOG_IDENTIFIER=sshd
```

`systemctl status` 只显示有限的最近日志，故障分析应使用明确时间范围的 `journalctl`。时钟跳变、时区差异和多机时间不同步会破坏事件关联。

### 13.2 journal 持久化与清理

日志可能保存在 `/run/log/journal/`（易失）或 `/var/log/journal/`（持久），实际行为由 journald 配置、发行版和存储状态决定。

```bash
journalctl --disk-usage
journalctl --verify
```

`journalctl --vacuum-time=`、`--vacuum-size=` 会删除归档 journal。执行前确认法规/审计保留、远程汇聚、当前磁盘压力和可恢复性；真空操作不是日志轮转策略的替代品。

### 13.3 传统日志文件与轮转

常见路径因发行版和服务而异：

| 类型 | Debian/Ubuntu 常见 | RHEL/Fedora 常见 |
| --- | --- | --- |
| 系统/守护进程 | `/var/log/syslog` | `/var/log/messages` |
| 认证 | `/var/log/auth.log` | `/var/log/secure` |
| 内核/启动 | journal、`/var/log/kern.log` 等 | journal、`/var/log/dmesg` 等 |

先查看服务配置、`systemctl cat` 和 journal，不要假定固定文件存在。

```bash
tail -F /var/log/myapp/app.log
zgrep -n -- 'ERROR' /var/log/myapp/app.log.*.gz
sudo logrotate -d /etc/logrotate.conf
```

- `logrotate -d` 调试配置而不执行轮转；`-f` 强制轮转，会改变状态，不能混淆。
- 不要通过直接截断未知活跃日志来解决空间问题。先确认日志写入者、轮转方式、已删除仍打开文件和保留要求。
- 应用是否能在轮转后重新打开文件取决于 copytruncate、信号或服务自身机制；选错策略会丢日志或长期占用旧文件。

### 13.4 dmesg 与内核事件

```bash
dmesg --level=err,warn
dmesg --follow
journalctl -k -b
```

`dmesg` 读取内核 ring buffer，权限可能受 `kernel.dmesg_restrict` 限制。`dmesg --ctime` 把单调时间近似转换成墙钟时间，系统休眠或时钟调整后未必适合严格取证；需要可靠时间线时优先结合 journal 的持久时间戳和外部监控。

常见关注词包括 `oom`、`out of memory`、`I/O error`、`reset`、`segfault`、`blocked for more than`，但日志片段必须结合设备、进程、时间和上游事件解释。

### 13.5 主动写日志与审计工具

```bash
logger -t maintenance 'configuration validation passed'
logger -p user.warning -t myapp 'degraded dependency'
```

`logger` 适合脚本把事件送入系统日志，但不得写入密码、Token、完整请求正文或不必要的个人数据。

启用 auditd 的系统可使用：

```bash
sudo ausearch -m AVC,USER_AUTH,USER_LOGIN --start today
sudo aureport --auth
```

审计规则、事件字段与保留策略需要结合发行版和合规要求设计。`ausearch -m AVC` 也常用于 SELinux 拒绝分析。

## 14. cron、at 与 systemd timer

### 14.1 用户 crontab

```bash
crontab -l
crontab -e
```

用户 crontab 每行由 5 个时间字段和命令组成：

```text
┌──────── minute        0-59
│ ┌────── hour          0-23
│ │ ┌──── day of month  1-31
│ │ │ ┌── month         1-12
│ │ │ │ ┌ day of week   0-7（0 和 7 通常都表示周日）
│ │ │ │ │
* * * * * command
```

示例：

```cron
SHELL=/bin/bash
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

15 2 * * * /usr/local/sbin/backup-job >>"$HOME/.local/state/backup-job.log" 2>&1
```

关键边界：

- `/etc/crontab` 和 `/etc/cron.d/*` 通常在时间字段后额外包含“运行用户”字段，不能直接复制到用户 crontab。
- cron 环境精简、工作目录不确定，应使用绝对路径并显式设置所需环境。
- 普通用户应预先创建仅自己可写的日志目录，例如 `install -d -m 0700 "$HOME/.local/state"`；`/var/log` 通常需要管理员预创建文件、设置属主并配置轮转。
- crontab 中 `%` 在部分实现里会被转换为换行并把后续内容送入标准输入，需要反斜杠转义。
- “月中日期”和“星期”同时受限时，部分 cron 实现按 OR 语义匹配；复杂日历应验证实现或使用 systemd timer。
- 时区、夏令时和主机停机可能导致任务重复或错过。
- `crontab -r` 会删除当前用户整个 crontab，执行前先 `crontab -l` 备份并审查。

防止同一任务并发可使用 util-linux `flock` `[可选/常见]`：

```cron
*/5 * * * * /usr/bin/flock -n "$HOME/.local/state/my-job.lock" /usr/local/bin/my-job
```

锁文件的父目录应预先创建，且只允许调用用户写入，避免其他用户替换锁文件；同时为任务设置超时、日志、失败通知和幂等语义。

### 14.2 at：一次性任务

```bash
printf '%s\n' '/usr/local/bin/one-time-job' | at now + 1 hour
atq
at -c JOB_ID
atrm JOB_ID
```

`at` 依赖 `atd` 服务，环境会在提交时捕获部分变量，但工作目录、凭据有效期和输出投递仍需验证。删除任务前用 `atq`/`at -c` 核对 ID 与内容。

### 14.3 systemd timer

查看现有 timer：

```bash
systemctl list-timers --all
systemctl status TIMER_NAME.timer
journalctl -u TIMER_NAME.service
```

一个最小系统级例子由 service 和 timer 两个 unit 组成：

```ini
# /etc/systemd/system/backup-job.service
[Unit]
Description=Run the controlled backup job

[Service]
Type=oneshot
User=BACKUP_USER
Group=BACKUP_GROUP
UMask=0077
NoNewPrivileges=true
PrivateTmp=true
ExecStart=/usr/local/sbin/backup-job
```

```ini
# /etc/systemd/system/backup-job.timer
[Unit]
Description=Run backup job every day

[Timer]
OnCalendar=*-*-* 02:15:00
Persistent=true
RandomizedDelaySec=10m
Unit=backup-job.service

[Install]
WantedBy=timers.target
```

部署流程：

```bash
sudo systemd-analyze verify /etc/systemd/system/backup-job.service /etc/systemd/system/backup-job.timer
sudo systemctl daemon-reload
sudo systemctl enable --now backup-job.timer
systemctl list-timers --all
```

- `Persistent=true` 可在主机恢复后补触发停机期间错过的日历任务，但不会重放每一次错过运行。
- `RandomizedDelaySec` 可降低大量主机同一时刻启动任务的尖峰。
- timer 激活 service，任务结果和日志应查 `.service` unit。
- 系统级 service 省略 `User=`/`Group=` 时默认以 root 运行。示例中的全大写账户占位符应替换为预先创建的专用服务账户，并确保脚本、输入与输出路径的所有权正确；确实需要 root 时应记录理由、可写路径和脚本完整性保护，并按任务评估 `ProtectSystem=`、`ReadWritePaths=` 等进一步限制。
- systemd `ExecStart` 不默认使用 Shell；它有自己的环境变量替换规则，但不会按 Shell 解释重定向、管道、glob 或命令替换。

## 15. 磁盘、分区、文件系统与挂载

### 15.1 建立存储拓扑基线

```bash
lsblk -o NAME,MAJ:MIN,SIZE,TYPE,FSTYPE,FSVER,LABEL,UUID,MOUNTPOINTS,MODEL,SERIAL
blkid
findmnt
findmnt -T /path/to/file
cat /proc/mdstat
pvs
vgs
lvs -a -o +devices
```

| 命令 | 说明 |
| --- | --- |
| `lsblk` | 展示块设备、分区、映射层和挂载点；来自 util-linux |
| `blkid` | 查询文件系统/分区签名和 UUID，完整结果可能需要特权 |
| `findmnt` | 以可解析方式查看挂载关系，比解析 `mount` 文本更稳妥 |
| `/proc/mdstat` | Linux MD 软件 RAID 摘要 |
| `pvs/vgs/lvs` | LVM 物理卷、卷组和逻辑卷状态 |

设备名（例如磁盘枚举顺序）可能在重启、硬件变化或云平台迁移后改变。持久配置优先使用经过核对的 `UUID=`、`PARTUUID=`、LVM 路径或平台稳定标识。

### 15.2 df、du 与 inode

```bash
df -hT
df -ih
du -xhd1 /var | sort -h
du -xsh /var/log
sudo lsof +L1
```

- `df` 查询文件系统分配统计；`du` 遍历可见目录项并累计文件占用，两者口径不同。
- `df -i` 检查 inode，海量小文件可能让 inode 耗尽，即使仍有数据块空间也无法创建文件。
- GNU `du -x` 不跨文件系统，避免进入其他挂载；`--max-depth` 的长选项和 `-d` 支持因实现而异。
- `du -sh *` 会漏掉隐藏项，并可能因权限、硬链接、稀疏文件、快照和挂载覆盖产生误解。
- 文件已删除但仍被进程打开时，`du` 看不到目录项，`df` 却仍显示空间占用；使用 `lsof +L1` 定位。
- ext 系文件系统可能为特权用户保留块；配额、CoW、压缩和快照也会让“逻辑大小”与“物理占用”不同。

查找大型文件时先限制文件系统边界和输出数量：

```bash
find /var -xdev -type f -size +1G -printf '%s %p\n' | sort -n | tail -n 50
```

这会遍历目录树并产生 I/O，繁忙主机应选择低峰、缩小路径或使用存储平台索引。

### 15.3 挂载与卸载

只读检查：

```bash
findmnt /mount/point
mountpoint /mount/point
findmnt -no SOURCE,FSTYPE,OPTIONS -T /path/to/file
```

临时挂载的通用形式：

```bash
sudo mount -o ro /dev/DEVICE /mount/point
sudo umount /mount/point
```

> **谨慎操作**
> `/dev/DEVICE` 必须替换为经过 `lsblk`、型号、序列号、签名和挂载状态共同确认的目标。文件系统类型、加密、LVM、RAID 和网络存储需要各自的挂载参数；不要把示例直接用于未知设备。

`mount -o ro` 限制挂载后的常规文件系统写入，但不等于底层介质绝对零写入；部分日志型文件系统可能在只读挂载过程中回放 journal。取证或故障介质应使用快照、受控镜像或硬件/块设备写保护，并根据具体文件系统评估 `noload`、`norecovery` 等“不回放日志”选项及其一致性代价，不能照搬统一参数。

卸载失败时先找占用者：

```bash
findmnt /mount/point
sudo fuser -vm /mount/point
sudo lsof +f -- /mount/point
```

强制/懒卸载可能让进程继续持有不可见路径或造成网络文件系统数据风险，不应作为默认处理。先停止正确的服务、退出工作目录并解除 bind/submount 依赖。

### 15.4 /etc/fstab

典型字段：

```text
UUID=...  /srv/data  ext4  defaults,nofail  0  2
```

| 字段 | 含义 |
| --- | --- |
| 1 | 设备、UUID、LABEL 或网络文件系统源 |
| 2 | 挂载点 |
| 3 | 文件系统类型 |
| 4 | 逗号分隔选项 |
| 5 | dump 备份标志，现代环境通常为 0 |
| 6 | 启动时 fsck 顺序；根常为 1，其他本地文件系统常为 2，禁用为 0 |

安全变更流程：

1. 保留 `/etc/fstab` 原内容和远程/控制台恢复通道。
2. 用 `lsblk -f`、`blkid`、`findmnt` 核对源、文件系统和挂载点。
3. 使用 `sudoedit /etc/fstab` 修改。
4. 只读验证语法和引用：

    ```bash
    sudo findmnt --verify --verbose
    ```

5. 在评估影响后测试对应挂载。`mount -a` 会实际挂载/重挂符合条件的条目，不是纯验证命令。
6. 用 `findmnt`、读写测试、服务日志和重启演练验证。

`nofail`、`_netdev`、`x-systemd.automount`、超时等选项会改变启动依赖和失败语义，不能只为“避免卡启动”而盲目添加。

### 15.5 分区、签名与格式化：高风险区

只读盘点：

```bash
sudo fdisk -l
sudo parted -l
sudo wipefs -n /dev/DEVICE
sudo file -s /dev/DEVICE
```

> **谨慎操作**
> `fdisk`/`parted` 写分区表、`wipefs` 去签名、`mkfs.*` 格式化、`dd` 原始写入以及 LVM/RAID 创建命令都能在数秒内破坏数据。实际变更前至少核对设备路径、容量、型号、序列号、WWN、云盘 ID、当前挂载、LVM/RAID/加密关系、备份恢复测试和双人复核。不要依赖 `/dev/sdX` 字母猜设备。

本文只给出识别命令，不提供可直接复制的格式化或清签名命令。正式 runbook 应写明：目标唯一标识、期望分区表、对齐、文件系统、标签/UUID、挂载配置、验证、回滚和数据恢复责任人。

关于 `dd`：它是无文件系统认知的字节复制工具，`if=` 与 `of=` 写反即可覆盖源盘；进度显示、块大小或 `conv=fsync` 都不能降低目标选择错误的破坏性。优先使用针对任务设计且带校验/确认的镜像工具。

### 15.6 文件系统检查、修复与扩缩容

- `fsck` 是文件系统检查前端，通常不应对正在读写挂载的文件系统执行修复。
- ext2/3/4 常使用 `e2fsck`；离线缩容和扩容步骤必须与分区/LVM 边界一致。
- XFS 使用 `xfs_repair` 做离线修复，挂载中的扩容常使用 `xfs_growfs`；XFS 不支持直接缩容。
- Btrfs、ZFS 等有自己的 scrub、check、快照和修复语义，不能套用 ext/XFS 命令。
- “只读检查”选项也可能产生大量 I/O，且某些工具所谓只读模式有边界；先读对应文件系统官方手册。

修复前应：确认备份、卸载/进入救援环境、记录内核错误、检查底层硬件/RAID、使用正确版本工具，并明确修复可能丢弃无法恢复的元数据。不要对发生硬件故障的原盘反复尝试写修复，优先考虑受控成像和专业恢复流程。

### 15.7 LVM

只读检查：

```bash
pvs -o +pv_used
vgs -o +vg_free
lvs -a -o lv_name,vg_name,lv_size,segtype,devices,data_percent,metadata_percent
lsblk -f
findmnt
```

LVM 层次为 PV（物理卷）→ VG（卷组）→ LV（逻辑卷）→ 文件系统/交换空间。扩展 LV 不一定自动扩展其中的文件系统；缩小文件系统、LV 和底层分区的顺序及可行性因文件系统而异。

某些 LVM 版本支持在扩展 LV 时调用文件系统工具：

```text
lvextend --resizefs --size +SIZE /dev/VG_NAME/LV_NAME
```

这是高风险模板而不是即用命令。执行前必须确认 VG 空闲、快照/薄池状态、文件系统支持、备份、设备路径和业务窗口；执行后用 `lvs`、`lsblk`、`findmnt`、`df` 与应用读写验证。本文不提供通用缩容步骤，因为 XFS 无法缩容，ext 文件系统缩容通常要求离线且顺序错误会直接截断数据。

### 15.8 swap

```bash
swapon --show
free -h
cat /proc/swaps
```

`swapon`/`swapoff` 会改变内存回收空间。关闭 swap 前必须确认物理内存和 cgroup 余量足以容纳当前页，否则可能触发 OOM 或长时间抖动。swap 文件还受文件系统（例如 CoW）和权限要求影响；持久配置通常通过 `/etc/fstab` 管理。

### 15.9 磁盘健康、RAID 与 I/O

```bash
sudo smartctl -a /dev/DEVICE
sudo nvme smart-log /dev/DEVICE
cat /proc/mdstat
sudo mdadm --detail /dev/MD_DEVICE
iostat -xz 1
iotop
```

这些工具通常需要 `smartmontools`、`nvme-cli`、`mdadm`、`sysstat` 或 `iotop` 包。SMART “PASSED” 不保证磁盘健康；应结合介质错误、重映射、CRC、温度、寿命、控制器日志、阵列状态和厂商指标。云盘还需查看平台层延迟、吞吐/IOPS 配额与突发余额。

## 16. 网络、DNS、TLS 与防火墙

### 16.1 分层排查顺序

网络故障应逐层验证，而不是只运行 `ping`：

```text
链路/接口 → 地址 → 路由/策略路由 → 名称解析 → 本地监听
→ TCP/UDP 可达 → TLS → HTTP/应用协议 → 外部路径/负载均衡
```

每一层都要区分“本机配置”“运行时状态”“持久配置”和“对端/中间网络设备”。

### 16.2 iproute2：接口、地址、路由与邻居

```bash
ip -brief link
ip -brief address
ip address show dev INTERFACE
ip route
ip -6 route
ip route get 203.0.113.10
ip neigh
ip rule
```

| 命令 | 说明 |
| --- | --- |
| `ip link` | 链路状态、MTU、MAC 和接口标志 |
| `ip address` | IPv4/IPv6 地址与作用域 |
| `ip route` | 主路由表；策略路由环境还需 `ip rule` 和其他表 |
| `ip route get DEST` | 查询内核对具体目标的实际选路、源地址和出口 |
| `ip neigh` | ARP/NDP 邻居缓存 |

`ip address add`、`ip route add` 等修改通常只影响当前运行状态，重启后是否保留取决于 NetworkManager、systemd-networkd、netplan、ifupdown、云初始化或发行版网络配置。先确认管理者，避免多个工具互相覆盖。

NetworkManager 只读检查：

```bash
nmcli general status
nmcli device status
nmcli connection show
nmcli device show INTERFACE
```

### 16.3 socket 与监听端口

```bash
ss -lntup
ss -tan state established
ss -s
lsof -iTCP:443 -sTCP:LISTEN -nP
```

常用 `ss` 选项：`-l` 监听、`-n` 不解析名称、`-t` TCP、`-u` UDP、`-p` 进程、`-a` 全部。非特权用户可能看不到其他进程详情。UDP 没有 TCP 式 LISTEN 握手状态，`-l` 只是显示未连接/可接收的数据报 socket。

“端口已监听”只证明本机有 socket：还要检查绑定地址（`127.0.0.1`、`0.0.0.0`、`::` 或指定地址）、network namespace、防火墙、路由、负载均衡和应用健康。

传统工具迁移：

| 传统 net-tools | 现代常用替代 |
| --- | --- |
| `ifconfig` | `ip address`、`ip link` |
| `route` | `ip route` |
| `arp` | `ip neigh` |
| `netstat` | `ss` |

旧工具并非在所有系统中移除，但新脚本和排障记录应优先使用 iproute2，并理解两者输出不可简单逐字段替换。

### 16.4 DNS 与系统名称解析

```bash
getent ahosts example.com
getent hosts example.com
resolvectl status
resolvectl query example.com
dig example.com A
dig example.com AAAA
dig +trace example.com
host example.com
```

- `getent` 走系统 NSS 解析链，可能综合 `/etc/hosts`、DNS、mDNS、LDAP 等，更接近应用看到的结果。
- `dig`/`host` 直接查询 DNS，适合分析记录、权威链和指定服务器，但不会按一般 NSS 顺序读取 `/etc/hosts`。
- `resolvectl` 适用于 systemd-resolved，能展示每链路 DNS、搜索域和缓存结果。
- `/etc/resolv.conf` 可能是 NetworkManager、systemd-resolved、DHCP 客户端或容器运行时生成的文件/符号链接；直接编辑前先确认所有者。
- DNS 成功不代表 TCP/TLS/应用成功，DNS 失败也可能只影响某一地址族、搜索域或 split DNS 视图。

检查 NSS 配置：

```bash
grep -E '^(hosts|passwd|group):' /etc/nsswitch.conf
readlink -f /etc/resolv.conf
```

### 16.5 ICMP、路径与端口连通性

```bash
ping -c 4 192.0.2.10
ping -6 -c 4 2001:db8::10
tracepath example.com
traceroute example.com
mtr --report --report-cycles 20 example.com
nc -vz -w 3 example.com 443
```

`tracepath`、`traceroute`、`mtr`、`nc` 常需额外安装；Netcat 存在 OpenBSD、traditional、Nmap ncat、BusyBox 等实现，选项可能不同。

- ping 不通可能只是 ICMP 被过滤；ping 成功也不能证明目标应用健康。
- traceroute 中间跳不回应不等于数据路径在该处中断；控制面响应和实际转发优先级不同。
- `nc -z` 只探测连接/端口，不执行 TLS 或应用协议握手。
- UDP 连通性无法像 TCP 一样通过一次连接建立可靠判断，需要了解应用协议和 ICMP 错误行为。

### 16.6 curl、wget 与 HTTP 诊断

```bash
curl --fail-with-body --silent --show-error \
  --connect-timeout 5 --max-time 15 \
  https://example.com/health

curl -v --connect-timeout 5 https://example.com/
curl -I https://example.com/
curl --resolve example.com:443:192.0.2.10 https://example.com/
wget --server-response --spider https://example.com/
```

关键语义：

- curl 默认把 HTTP 4xx/5xx 当作成功完成的 HTTP 传输，退出码仍可能为 0；脚本使用较新版本的 `--fail-with-body` 或兼容性更广的 `--fail`。
- `-I` 发送 HEAD，请求路径可能与 GET 的应用行为不同。
- `--resolve` 临时指定“主机:端口→地址”，同时保留正确的 Host/SNI，适合隔离 DNS 与后端问题。
- `-v` 可能输出完整的 `Authorization`、`Cookie`、代理认证等实际凭据，不能依赖特定 curl 版本自动隐藏；诊断日志应最小化、脱敏并控制权限。
- `-k/--insecure` 关闭 TLS 证书验证，只能在明确受控的短暂诊断中使用，不能作为证书问题的长期修复。
- 下载文件时同时限制重定向、大小、超时和保存路径，并从可信渠道校验签名/摘要。

### 16.7 TLS 握手检查

```bash
openssl s_client \
  -connect example.com:443 \
  -servername example.com \
  -verify_hostname example.com \
  -verify_return_error </dev/null
```

检查协议、证书链、SAN、有效期、SNI 和验证错误。`-servername` 只设置 SNI，`-verify_hostname` 才要求证书身份匹配；验证 IP 身份时，在支持的版本中使用 `-verify_ip`。旧版 OpenSSL/LibreSSL 若不支持这些参数，应结合 `curl` 或应用实际 TLS 客户端验证。系统时间错误、代理、中间证书和不同运行时的 CA 存储都会影响结果。

### 16.8 tcpdump 与链路诊断

```bash
sudo tcpdump -D
sudo tcpdump -ni any -c 100 'host 192.0.2.10 and port 443'
sudo tcpdump -ni INTERFACE -s 0 -c 1000 -w /secure/path/capture.pcap 'tcp port 443'
ethtool INTERFACE
ethtool -S INTERFACE
```

> **警告**
> 抓包可能包含账号、Cookie、Token、业务正文和个人数据，并增加 CPU、磁盘与网络压力。必须有授权，限制接口、过滤器、包数/文件大小和保存时间，把 pcap 存到受控路径并按敏感数据处理。

`-n` 禁止名称解析，避免额外 DNS 流量和延迟；`-i any` 在 Linux 上观察多接口但链路层信息与 offload 行为可能不同。校验和“错误”有时来自网卡卸载，需结合抓包位置判断。

需要较长时间抓包时，应按本机 tcpdump 版本验证 `-C`（单文件大小）和 `-W`（文件数量）轮转组合，并同时监控剩余空间；包数/文件上限不能替代到期清理和访问控制。

### 16.9 防火墙框架

常见栈可能包含 nftables、iptables-nft 兼容层，以及 firewalld/UFW 等管理前端。不要同时用多个前端盲目修改同一规则集。

只读检查：

```bash
sudo nft list ruleset
sudo firewall-cmd --get-active-zones
sudo firewall-cmd --list-all
sudo ufw status verbose
sudo iptables -S
```

- `nft` 是现代内核包过滤框架的主要用户接口。
- firewalld 管理 zone、service 与运行时/永久配置；运行时变更和永久变更是两套状态。
- UFW 是面向简化策略的前端，底层实现可随发行版变化。
- `iptables` 可能操作 legacy 后端或 nft 兼容后端，先检查系统选择。

> **谨慎操作**
> 远程主机修改防火墙前应保留已建立的管理会话、显式允许管理源和端口、准备自动回滚/带外控制，并先做运行时小范围验证。本文不提供清空规则集或默认全拒绝的即用命令，因为顺序错误会立即造成失联。

验证防火墙变更不能只看规则文本，还要从本机、同网段和真实外部路径测试目标协议，并检查 NAT、云安全组、负载均衡和主机防火墙的叠加效果。

## 17. SSH、远程传输与 rsync

### 17.1 连接与客户端配置

```bash
ssh USER_NAME@HOST_NAME
ssh -p 2222 USER_NAME@HOST_NAME
ssh -vvv USER_NAME@HOST_NAME
```

`-vvv` 输出协商、配置来源、密钥尝试和认证阶段，可能包含用户名、主机、路径等敏感元数据。排障日志应脱敏。

`~/.ssh/config` 可减少重复参数：

```sshconfig
Host app-prod
    HostName app.example.com
    User deploy
    Port 22
    IdentityFile ~/.ssh/id_ed25519_app
    IdentitiesOnly yes
    ServerAliveInterval 30
    ServerAliveCountMax 3
```

查看最终生效配置：

```bash
ssh -G app-prod | less
```

配置有系统级、用户级、Host 匹配和命令行多层来源；`ssh -G` 有助于排查“明明写了配置却未生效”。

### 17.2 密钥、权限与 agent

```bash
ssh-keygen -t ed25519 -a 64 -f ~/.ssh/id_ed25519_app
ssh-keygen -lf ~/.ssh/id_ed25519_app.pub
ssh-copy-id -i ~/.ssh/id_ed25519_app.pub USER_NAME@HOST_NAME
ssh-add -l
ssh-add ~/.ssh/id_ed25519_app
```

建议权限与所有权：

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/id_ed25519_app
chmod 600 ~/.ssh/authorized_keys
chmod 644 ~/.ssh/id_ed25519_app.pub
```

- 私钥应使用强口令并交由合适的 agent/密钥管理系统管理，不得提交 Git、放入镜像或共享聊天。
- `authorized_keys` 的目录链、文件属主和权限都会影响 sshd 是否接受；NFS、SELinux 和发行版策略还可能附加要求。
- agent 转发会让远端进程间接使用本地 agent，应仅对受信任主机按需启用，不要设为全局默认。

### 17.3 主机密钥验证

```bash
ssh-keygen -F HOST_NAME
ssh-keygen -F '[HOST_NAME]:2222'
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

首次连接或密钥变化时，应通过受信任的独立渠道核对指纹。`ssh-keyscan` 只能收集网络上返回的公钥，若没有额外验证，它本身不能建立信任。不要把 `StrictHostKeyChecking=no` 当作自动化常规方案。

确认为合法重装/轮换后，才可精确删除旧记录并重新核对：

```bash
ssh-keygen -R HOST_NAME
ssh-keygen -R '[HOST_NAME]:2222'
```

非默认端口的 known_hosts 键通常使用 `[HOST_NAME]:PORT` 形式，查询和删除时必须包含方括号与端口。

### 17.4 端口转发

```bash
ssh -N -L 127.0.0.1:15432:db.internal:5432 bastion.example.com
ssh -N -D 127.0.0.1:1080 bastion.example.com
ssh -N -R 127.0.0.1:18080:127.0.0.1:8080 bastion.example.com
```

| 类型 | 说明 |
| --- | --- |
| `-L` | 本地监听，经 SSH 访问远端可达的目标 |
| `-D` | 本地动态 SOCKS 代理 |
| `-R` | 远端监听，经 SSH 回连客户端可达的目标；受服务端策略限制 |
| `-N` | 不执行远端命令，只建立转发 |

监听地址使用 `127.0.0.1` 可避免无意暴露给其他主机。转发可能绕过正常网络边界和审计，必须符合组织授权与数据流策略。

### 17.5 服务端配置变更

```bash
sudo sshd -t
sudo sshd -T | less
systemctl status sshd.service --no-pager
journalctl -u sshd.service -b
```

unit 名可能是 `ssh.service`。安全变更流程：

1. 保留当前已认证会话和带外控制台。
2. 备份并用 `sudoedit` 修改正确的主配置或 include 片段。
3. 用 `sshd -t` 校验语法；需要分析最终值时用 `sshd -T`，Match 条件可要求额外上下文参数。
4. 使用服务支持的 reload，而不是立即中断全部连接。
5. 从新的独立终端完成一次真实登录，再关闭旧会话。

禁用密码认证、禁止 root、调整 AllowUsers/Match 或端口之前，必须先验证密钥、sudo 权限、防火墙、SELinux 端口标签和恢复路径。

### 17.6 scp 与 sftp

```bash
scp -P 2222 local.file USER_NAME@HOST_NAME:/remote/path/
scp -p local.file USER_NAME@HOST_NAME:/remote/path/
sftp -P 2222 USER_NAME@HOST_NAME
```

- SSH 用小写 `-p` 指定端口；`scp`/`sftp` 用大写 `-P`。`scp -p` 表示保留时间和模式。
- 现代 OpenSSH 的 scp 默认使用 SFTP 协议，但旧服务器、通配和兼容选项行为可能不同。
- 远端路径、Shell 展开和目标覆盖语义需在具体版本验证；批量和可恢复传输优先考虑 SFTP 或 rsync。

### 17.7 rsync 语义与安全流程

```bash
rsync -a --dry-run --itemize-changes source/ destination/
rsync -aHAX --numeric-ids --dry-run source/ destination/
rsync -a --partial --progress source/ USER_NAME@HOST_NAME:/remote/path/
```

源路径末尾斜杠至关重要：

```text
rsync -a source  destination/   → destination/source/...
rsync -a source/ destination/   → destination/...（只复制 source 的内容）
```

`-a` 近似 `-rlptgoD`，不包含硬链接、ACL 和扩展属性；需要时显式加 `-HAX`，并确认两端文件系统与权限支持。`--numeric-ids` 适合需要按数字身份还原的受控系统备份，但跨环境可能映射到错误账户。

删除同步流程：

```bash
rsync -a --delete --dry-run --itemize-changes source/ destination/
```

> **谨慎操作**
> `--delete` 会删除目标中源端不存在的内容。必须先确认源/目标和尾斜杠、挂载是否在线、排除规则、dry-run 输出与备份。挂载失败导致目标目录变成空本地目录，是常见灾难来源，可用 `mountpoint`/`findmnt` 做前置断言。

rsync 是同步工具，不自动提供历史版本、离线副本、不可变性或勒索软件隔离，因此“同步成功”不等于“备份合格”。备份还需定义保留、加密、校验、恢复演练和异地/离线策略。

## 18. 内核、硬件、sysctl 与资源限制

### 18.1 CPU、内存、总线与虚拟化

```bash
lscpu
nproc
free -h
grep -E '^(MemTotal|MemAvailable|SwapTotal|SwapFree):' /proc/meminfo
lspci -nnk
lsusb -t
sudo dmidecode -t system
sudo dmidecode -t memory
systemd-detect-virt
sensors
```

| 命令 | 来源/用途 |
| --- | --- |
| `lscpu` | util-linux；CPU 架构、拓扑、NUMA 与漏洞缓解摘要 |
| `nproc` | coreutils；当前进程可用的处理器数，可能受 affinity/cgroup 限制 |
| `lspci` / `lsusb` | PCI/USB 设备与驱动；通常来自 `pciutils`/`usbutils` |
| `dmidecode` | 读取固件 DMI/SMBIOS，值可能缺失或由虚拟化平台伪造 |
| `systemd-detect-virt` | 检测常见 VM/容器 `[systemd]` |
| `sensors` | 温度、电压和风扇 `[lm-sensors/可选]` |

云主机、容器和 VM 中看到的是平台暴露的视图，不一定等于物理硬件。`nproc`、`lscpu`、`/proc/cpuinfo` 与 cgroup CPU quota 可能表达不同限制，应结合运行时/编排器指标。

### 18.2 /proc、/sys 与设备事件

```bash
cat /proc/cmdline
cat /proc/mounts
cat /proc/interrupts
cat /proc/loadavg
udevadm info --query=all --name=/dev/DEVICE
udevadm monitor --kernel --udev
```

- `/proc` 是内核和进程状态的虚拟文件系统；许多文件读取时动态生成。
- `/sys` 展示设备、驱动、总线和内核对象，写入某些属性会立即改变硬件/内核运行状态。
- `udevadm monitor` 会持续输出设备事件，适合热插拔排查；`udevadm trigger` 会主动重放事件，不是只读命令。
- 不要把 `/proc`/`/sys` 的数值从一台机器机械复制到另一台机器。

### 18.3 内核模块

```bash
lsmod
modinfo MODULE_NAME
modprobe -n -v MODULE_NAME
sudo modprobe MODULE_NAME
```

`lsmod` 显示已加载模块及引用关系；`modinfo` 查看别名、参数、许可证、签名和文件路径；`modprobe -n -v` 预览依赖和将执行的动作。`modprobe` 会读取 `/etc/modprobe.d/` 等配置，其中的 `install` 规则还可能调用外部命令；持久加载和参数通常由 `/etc/modules-load.d/`、`/etc/modprobe.d/` 或 initramfs 管理。

> **谨慎操作**
> 加载未知模块会立即改变内核状态，并可能绑定存储、网络或其他设备；卸载存储、网络、文件系统、安全或虚拟化模块也可能立即中断业务。变更前检查模块来源/签名、依赖、参数、绑定设备、modprobe 配置、控制台与回滚路径，不要把加载或 `modprobe -r` 当作普通试错步骤。

### 18.4 sysctl：运行时内核参数

```bash
sysctl kernel.hostname
sysctl net.ipv4.ip_forward
sysctl -a | less
sudo sysctl -w net.ipv4.ip_forward=1
```

`sysctl -w` 通常只修改当前运行内核，重启后不会自动保留。持久化配置一般放在 `/etc/sysctl.d/NAME.conf`，再由启动流程或以下命令加载：

```bash
sudo sysctl --system
```

> **警告**
> `sysctl --system` 会加载多个目录中的全部配置并改变运行状态。网络转发、源路由校验、连接跟踪、虚拟内存、文件句柄和内核安全参数会影响整机与容器。先记录旧值、理解参数版本语义，在隔离环境和小范围主机验证；不要套用未经测量的“万能性能参数全集”。

查看持久配置来源：

```bash
grep -RIn --include='*.conf' -- 'net.ipv4.ip_forward' /etc/sysctl.conf /etc/sysctl.d 2>/dev/null
```

发行版还可能从 `/usr/lib/sysctl.d`、`/run/sysctl.d` 等目录加载配置，并按文件名优先级覆盖。

### 18.5 文件描述符、进程限制与 cgroup

```bash
ulimit -a
ulimit -n
prlimit --pid PID
cat /proc/PID/limits
systemctl show SERVICE_NAME.service -p LimitNOFILE -p MemoryMax -p CPUQuotaPerSecUSec
systemd-cgtop
```

- `ulimit` 是 Shell 内建命令，只影响当前 Shell 和后代；提高硬限制通常需要 PAM、systemd 或管理员配置。
- systemd unit 的 `LimitNOFILE=` 对应传统 rlimit，`MemoryMax=`、`CPUQuota=` 等属于 cgroup 资源控制，二者不是同一层。
- 容器限制应从容器运行时/cgroup 视角检查；宿主机 `free` 可能远高于容器可用额度。
- 把限制调得很大可能把故障从“快速拒绝”变成全局资源耗尽，必须结合容量和监控。

### 18.6 主机名与重启后验证

```bash
hostnamectl status
sudo hostnamectl set-hostname HOST_NAME
```

主机名变更可能影响证书、监控、日志、集群成员、`/etc/hosts` 和云平台元数据。变更前确认依赖，变更后从本机、DNS、应用和管理平台多层验证。内核、模块、sysctl、挂载和网络配置的最终验收通常还应包括一次受控重启。

## 19. Bash 自动化与脚本质量

### 19.1 解释器与基本骨架

需要 Bash 特性时明确声明，不要以 `/bin/sh` 启动后使用数组、`[[ ]]`、`source` 或 `pipefail`：

```bash
#!/usr/bin/env bash

set -Eeuo pipefail

main() {
    printf 'running as %s\n' "$(id -un)"
}

main "$@"
```

- `#!/usr/bin/env bash` 按 `PATH` 找 Bash，适合多种安装位置；高信任系统脚本可使用组织规定的固定路径，避免不可信 `PATH`。
- `set -e` 在条件、管道、子 Shell、命令替换和函数等上下文存在例外，不是完整异常处理机制。
- `set -u` 会让未定义变量报错，但可选变量需写成 `${name:-}` 等形式。
- `pipefail` 是 Bash 等 Shell 的扩展，不属于 POSIX sh。
- `set -x` 会把展开后的命令写到日志，极易泄露 Secret，只能在受控调试中使用并做好脱敏。

### 19.2 变量、数组与引用

```bash
readonly config_path='/etc/myapp/config.ini'
files=('first file' 'second-file')

for file_path in "${files[@]}"; do
    printf '%s\n' "$file_path"
done
```

基本规则：

- 变量引用默认写成 `"$variable"`；数组全部元素用 `"${array[@]}"`。
- 不使用 `eval` 拼接来自用户、文件或网络的命令。
- 输出任意数据优先 `printf '%s\n' "$value"`；不同 `echo` 实现对 `-n`、`-e` 和反斜杠处理不一致。
- 读取文本用 `IFS= read -r line`，避免丢失首尾空白和反斜杠。
- 机密输入可用 `read -r -s`，但仍需控制内存、子进程、core dump 和后续日志。

按行读取：

```bash
while IFS= read -r line || [[ -n $line ]]; do
    printf '%s\n' "$line"
done < input.txt
```

处理任意文件名应使用 glob 数组、`find -exec` 或 NUL 分隔，而不是命令替换。

### 19.3 条件、算术与参数

```bash
if [[ -r $config_path && -s $config_path ]]; then
    printf 'config is readable and non-empty\n'
fi

if (( retries > 3 )); then
    printf 'retry limit exceeded\n' >&2
fi
```

`[[ ... ]]` 是 Bash 条件语法，在其中变量通常不会发生普通分词/路径名展开，但右侧模式和正则仍有自身引用规则。POSIX sh 使用 `[ ... ]`/`test`，参数间空格不可省略。

使用 `getopts` 解析短选项比手工移动参数稳妥：

```bash
while getopts ':c:n' option; do
    case "$option" in
        c) config_path=$OPTARG ;;
        n) dry_run=true ;;
        :) printf 'option -%s requires an argument\n' "$OPTARG" >&2; exit 2 ;;
        \?) printf 'unknown option: -%s\n' "$OPTARG" >&2; exit 2 ;;
    esac
done
shift "$((OPTIND - 1))"
```

### 19.4 临时目录与清理

```bash
task_tmp_dir="$(mktemp -d)"
readonly task_tmp_dir

cleanup() {
    rm -rf -- "$task_tmp_dir"
}

trap cleanup EXIT
```

这里的递归删除仅限由成功的 `mktemp -d` 返回并立即设为只读的专用目录。实际脚本还应确保变量未被外部覆盖、目录不承载挂载点，并在清理失败时保留可诊断信息。不要把这一模式改成可能为空、为 `/` 或为共享目录的变量。

信号处理可记录中断并让 `EXIT` trap 统一清理：

```bash
trap 'printf "interrupted\n" >&2; exit 130' INT
trap 'printf "terminated\n" >&2; exit 143' TERM
```

### 19.5 并发、幂等与外部命令

- 重复执行脚本应得到相同期望状态；创建资源前查询现状，变更后验证。
- 对删除、同步、部署提供 `--dry-run`，并让预览与实际使用同一筛选逻辑。
- 使用 `flock` 或系统级调度互斥防止重入，但锁目录与异常释放语义要明确。
- 给网络请求和外部命令设置连接超时、总超时、有限重试与指数退避；只重试已知可安全重放的操作。
- 不在日志中记录 Secret；错误信息应包含操作、目标类别和退出码，而不是敏感参数。
- 使用结构化、带时间和关联 ID 的日志，明确标准输出与标准错误用途。

### 19.6 静态检查与测试

```bash
bash -n script.sh
shellcheck script.sh
bash -x script.sh
```

- `bash -n` 只检查语法，不执行脚本。
- ShellCheck `[可选]` 能发现常见引用、分词、不可移植性和错误处理问题，但提示仍需结合意图判断。
- `bash -x` 会执行并跟踪脚本，不能用于包含真实 Secret 或有副作用的未知脚本。
- 生产脚本应在容器/VM 等隔离环境测试正常、失败、超时、重复执行、并发和部分完成后的恢复路径。

## 20. 安全基线与强制访问控制

### 20.1 最小基线

1. 只运行需要的服务，用 `ss -lntup` 和 `systemctl list-units` 定期盘点。
2. 从受信任仓库及时更新，记录重启和回滚要求。
3. 使用独立服务账户、最小文件权限、最小 sudo 规则和最小 capability。
4. SSH 使用受管理密钥、主机密钥验证和明确来源限制；保留审计与恢复通道。
5. 使用一个明确的防火墙管理层，并同时考虑云安全组、负载均衡和容器网络策略。
6. 保证时间同步、日志持久化/汇聚和审计保留。
7. Secret 不进入 Git、镜像层、Shell 历史、命令参数或普通日志。
8. 备份采用版本化、隔离、校验和定期恢复演练，而不是仅同步一份在线副本。

### 20.2 SELinux

```bash
getenforce
sestatus
ls -Zd /srv/myapp
ps -eZ | less
sudo ausearch -m AVC --start recent
```

SELinux 拒绝排查顺序：

1. 确认传统权限、ACL 和挂载选项本身正确。
2. 从 audit 日志读取 AVC，识别源域、目标类型、对象类别和被拒权限。
3. 自定义路径需要特殊类型时，先使用 `semanage fcontext` 建立并核验持久规则，而不是只做临时 `chcon`。
4. 在明确是否跨文件系统后先预览标准策略将做的修改：

    ```bash
    sudo restorecon -nRvx /srv/myapp
    ```

5. 审查预览无误后，再去掉 `-n` 应用标签。这里的 `-x` 限制在当前文件系统；确实需要跨挂载处理时应逐个明确目标，而不是盲目递归。
6. 只有业务确实需要新访问时才设计最小策略，并审查 `audit2allow` 生成结果。

不要把 `setenforce 0` 或永久禁用 SELinux 当作权限问题修复。它会移除整层隔离、掩盖根因，并改变生产风险。

### 20.3 AppArmor

```bash
sudo aa-status
journalctl -k -b | grep -i apparmor
```

AppArmor 通过路径型 profile 约束程序。排查时确认 profile、可执行文件路径、include/abstraction、被拒操作和 complain/enforce 状态。切到 complain 模式会降低保护，只应在受控测试和明确时间窗口使用，并在修复 profile 后恢复 enforce。

### 20.4 挂载、安全属性与临时数据

- `nodev`、`nosuid`、`noexec` 可减少某些挂载点攻击面，但会影响设备文件、setuid/capability 与直接执行；它们不是恶意脚本的绝对阻断。
- `/tmp` 等共享目录依赖 sticky bit；应用临时内容仍应使用 `mktemp` 和最小权限。
- `lsattr` 的 immutable 标志、ACL、SELinux/AppArmor 和只读挂载都可能造成写入失败，应按层排查。
- core dump、swap、备份、日志和诊断包都可能包含 Secret，需要加密、访问控制和生命周期管理。

### 20.5 下载与执行边界

推荐流程：

```bash
curl --fail --location --output installer.sh https://example.com/installer.sh
less installer.sh
sha256sum installer.sh
bash -n installer.sh
```

摘要必须来自独立可信渠道，并优先验证发布签名。之后仍应在低权限、隔离环境审查其网络访问、安装路径、持久化、sudo 请求与回滚。不要因为 TLS 成功就假定脚本可信，也不要用关闭证书校验解决下载问题。

## 21. 场景化运维排障手册

### 21.1 通用方法

排障遵循“观察 → 定位 → 变更 → 验证 → 回滚”：

1. 明确期望状态、故障开始时间、影响范围、复现条件和最近变更。
2. 记录主机时间、版本、配置摘要、监控和相关日志，避免先重启抹掉现场。
3. 从资源、进程、服务、socket、网络到应用逐层缩小，不凭单条告警直接归因。
4. 区分相关性与因果，提出能被下一条只读检查证伪的假设。
5. 一次只做一个小变更，提前准备回滚和失联恢复。
6. 修复后同时验证功能、外部路径、错误日志、资源趋势和一段稳定观察窗口。
7. 记录时间线、根因、触发条件、为什么监控未提前发现以及永久预防措施。

### 21.2 服务启动失败或反复重启

观察：

```bash
systemctl status SERVICE_NAME.service --no-pager
systemctl show SERVICE_NAME.service -p ActiveState -p SubState -p Result -p ExecMainStatus -p NRestarts
journalctl -u SERVICE_NAME.service -b --since '30 minutes ago'
systemctl cat SERVICE_NAME.service
systemctl list-dependencies SERVICE_NAME.service
```

定位顺序：

1. 读取第一条根因错误，而不是只看最后的“start request repeated too quickly”。
2. 用应用原生命令检查配置语法、证书、凭据和依赖。
3. 核对 `User=`、`Group=`、`WorkingDirectory=`、`Environment*=`、`ExecStart=` 路径与权限。
4. 检查端口冲突、磁盘/inode、只读文件系统、内存/cgroup 限制与 SELinux/AppArmor。
5. 手工复现时必须使用与 unit 相同的用户、环境和工作目录，避免“root 下能跑”误判。

修改后：

```bash
sudo systemctl daemon-reload
sudo systemctl restart SERVICE_NAME.service
systemctl is-active SERVICE_NAME.service
journalctl -u SERVICE_NAME.service --since '5 minutes ago'
```

`daemon-reload` 只在 unit 定义变化时需要。应用配置变化按服务能力使用 reload/restart，并执行真实健康检查。

### 21.3 端口无法访问

```bash
ss -lntup
curl --fail-with-body --connect-timeout 3 http://127.0.0.1:PORT/health
ip route get CLIENT_OR_SERVER_IP
getent ahosts HOST_NAME
sudo nft list ruleset
```

判断链：

1. 没有监听：回到服务进程和配置。
2. 只监听 `127.0.0.1`：远端无法直接访问，这是绑定地址问题而非一定是防火墙。
3. 本机访问失败：检查协议、路径、应用日志和本机策略。
4. 本机成功、远端失败：检查主机防火墙、云安全组、路由/NAT、负载均衡和对端出口。
5. TCP 成功、TLS/HTTP 失败：进入证书、SNI、Host、代理和应用层排查。

不要为了测试而直接清空防火墙；使用精确的只读计数器、抓包和临时最小规则验证假设。

### 21.4 CPU 高或 load average 高

```bash
uptime
top
ps -eo pid,ppid,user,stat,psr,%cpu,%mem,etime,cmd --sort=-%cpu | head -n 30
pidstat -u -t 1
vmstat 1
```

- CPU 使用高：识别进程/线程、user/system/iowait/steal 比例，结合部署、流量和 profiler。
- load 高且 CPU 空闲：查 `D` 状态、I/O、NFS、锁和内核堆栈，不要只扩 CPU。
- 虚拟机 steal 高：可能是宿主机争用；结合云平台指标。
- 单线程满核：整机平均可能不高，需看每 CPU 和线程。

进一步检查：

```bash
ps -eo state,pid,ppid,wchan:32,cmd | awk '$1 ~ /^D/'
iostat -xz 1
pidstat -d 1
journalctl -k -b -p warning
```

终止高 CPU 进程前确认它是否正执行恢复、压缩、数据库 checkpoint 或关键事务；优先限流、摘流或正常停止。

### 21.5 内存紧张、swap 或 OOM

```bash
free -h
vmstat 1
ps -eo pid,user,rss,vsz,%mem,etime,cmd --sort=-rss | head -n 30
grep -E '^(Rss|Pss|Private_(Clean|Dirty|Hugetlb)|Shared_(Clean|Dirty|Hugetlb)|Swap):' \
  /proc/PID/smaps_rollup
systemd-cgtop
journalctl -k -b | grep -Ei 'out of memory|oom|killed process'
```

判断要点：

- 重点看 `available`、持续换页 `si/so`、回收延迟和 OOM 日志，不把 page cache 简单视为泄漏。
- RSS 会重复计算共享页；PSS 更适合多进程共享库场景。
- 宿主机有余量不代表 cgroup/容器没触发 `MemoryMax`/OOM。
- 内核 OOM 日志中的“killed process”是受害者，不一定是最初泄漏者。
- swap 突然增长可能是压力结果，也可能是长期冷页；结合时间序列判断。

不要在压力高峰未经评估直接 `swapoff` 或清空缓存。先止住流量/任务、保留证据、按服务方式重启泄漏进程，并修复容量或代码根因。

### 21.6 磁盘空间或 inode 耗尽

```bash
df -hT
df -ih
findmnt
du -xhd1 /var | sort -h
sudo lsof +L1
journalctl --disk-usage
```

定位分支：

- `df` 满、`du` 也大：逐层缩小目录，识别业务数据、日志、缓存、快照或容器层。
- `df` 满、`du` 不大：查已删除仍打开文件、挂载覆盖、保留块、快照和文件系统错误。
- inode 满：查大量小文件、异常队列或缓存，不能只删除一个大文件。
- `/var` 满：检查 journal、应用日志、包缓存、容器镜像/层；使用各组件自己的清理与保留机制。

不要删除数据库文件、当前 journal、容器存储内部文件或未知日志。先停止增长源、确认保留要求，使用应用/日志系统提供的安全轮转或清理接口，最后验证空间确已释放。

### 21.7 I/O 延迟与 D 状态

```bash
vmstat 1
iostat -xz 1
pidstat -d 1
iotop
journalctl -k -b -p warning
```

检查：设备延迟与队列、读写吞吐、具体进程、文件系统错误、块设备 reset、RAID 重建、NFS/网络存储、云盘配额和数据库内部等待。`D` 状态进程通常在内核等待，`SIGKILL` 也要等等待返回才真正退出；根因常在存储或内核路径。

### 21.8 DNS、TLS 或 HTTP 异常

```bash
date --iso-8601=seconds
getent ahosts example.com
resolvectl query example.com
dig example.com A
ip route get 203.0.113.10
curl -v --connect-timeout 5 --max-time 15 https://example.com/
openssl s_client -connect example.com:443 -servername example.com -verify_hostname example.com -verify_return_error </dev/null
```

按层区分：

- `getent` 失败而 `dig` 成功：NSS、搜索域、`/etc/hosts`、systemd-resolved/NetworkManager 链路可能有问题。
- DNS 正确但连接超时：路由、防火墙、代理或对端监听。
- TCP 建立但 TLS 失败：时间、SNI、证书链、CA、协议/密码套件或中间代理。
- TLS 成功但 HTTP 错误：Host、路径、认证、应用依赖和负载均衡健康。

不要以修改 `/etc/hosts`、使用 IP 直连或 `curl -k` 作为长期修复；这些只能在明确的诊断假设下临时隔离某一层。

### 21.9 Permission denied

```bash
id
namei -l /path/to/file
stat /path/to/file
getfacl /path/to/file
findmnt -T /path/to/file -o TARGET,SOURCE,FSTYPE,OPTIONS
lsattr /path/to/file
getenforce
sudo ausearch -m AVC --start recent
```

逐层确认身份、父目录遍历、文件/父目录权限、ACL mask、只读/`noexec` 挂载、不可变标记、SELinux/AppArmor、容器只读层和 capability。不要看到拒绝就递归 `chmod 777` 或关闭安全模块。

### 21.10 SSH 登录失败

客户端：

```bash
ssh -vvv USER_NAME@HOST_NAME
getent ahosts HOST_NAME
nc -vz -w 3 HOST_NAME 22
```

服务端或控制台：

```bash
ss -lntp
systemctl status sshd.service --no-pager
journalctl -u sshd.service --since '15 minutes ago'
sudo sshd -t
getent passwd USER_NAME
namei -l /home/USER_NAME/.ssh/authorized_keys
```

检查网络与防火墙、监听地址、AllowUsers/Groups/Match、账户/密码有效期、Shell、家目录/密钥权限、密钥算法、SELinux/AppArmor 和认证后端。失败次数过多还可能触发 fail2ban/PAM/上游安全设备。始终保留现有会话直到新会话验证完成。

### 21.11 上次启动失败或启动缓慢

```bash
journalctl --list-boots
journalctl -b -1 -p warning
systemctl --failed
systemd-analyze critical-chain
sudo findmnt --verify --verbose
lsblk -f
```

常见方向包括 fstab 设备丢失/超时、文件系统错误、内核/驱动变更、initramfs、磁盘空间、网络在线等待和失败服务。若当前系统无法正常启动，应从带外控制台、救援内核或受信任恢复介质操作；先挂载只读并保留日志/配置，再修复。

### 21.12 command not found 或执行格式错误

```bash
type -a COMMAND_NAME
command -v COMMAND_NAME
printf '%s\n' "$PATH" | tr ':' '\n'
file /path/to/program
ldd /path/to/program
```

排查：

- 命令是否安装、名称是否正确、当前 Shell 是否缓存旧路径（`hash -r`）。
- `PATH` 是否在 sudo、cron、systemd 或容器中不同。
- 文件是否有执行权限，所在挂载是否 `noexec`，解释器 shebang 是否存在。
- 二进制架构、动态链接器和库是否匹配。`ldd` 不应对不可信二进制直接使用，因为部分实现/文件可能导致代码执行；可先用 `file`、`readelf -l/-d` 静态检查。
- Windows CRLF 可能让 shebang 解释器路径末尾出现 `\r`。

## 22. 兼容性、目录速查与参考资料

### 22.1 常见目录用途

| 路径 | 常见用途 |
| --- | --- |
| `/etc` | 主机级配置，不应存放普通可执行程序 |
| `/var` | 日志、队列、缓存、数据库等可变数据 |
| `/usr` | 发行版/管理员提供的只读式用户空间程序与数据 |
| `/usr/local` | 本机管理员安装、避免被发行版包覆盖的内容 |
| `/opt` | 附加应用的自包含目录，具体布局由应用定义 |
| `/run` | 本次启动的易失运行状态，如 PID、socket、lock |
| `/tmp` | 临时文件，清理和持久性策略不保证；通常为共享 sticky 目录 |
| `/home` | 普通用户家目录，实际位置可由 NSS/组织改变 |
| `/root` | root 用户家目录，不等同于文件系统根 `/` |
| `/proc` | 进程与内核虚拟接口 |
| `/sys` | 设备和内核对象虚拟接口 |
| `/dev` | 设备节点及伪设备 |
| `/boot` | 内核、initramfs、引导加载器相关文件 |
| `/srv` | 站点/服务提供的数据，是否采用依发行版与组织规范 |
| `/mnt` / `/media` | 临时挂载 / 可移动介质的常见约定 |

目录布局受 Filesystem Hierarchy Standard、发行版、容器镜像和应用约定影响。例如现代 merged-/usr 系统中 `/bin`、`/sbin`、`/lib` 可能链接到 `/usr` 下对应目录。

### 22.2 常见可选工具与包名差异

### 22.3 GNU、POSIX、BusyBox 与实现差异

以下常见写法不是完全可移植的 POSIX 接口：

- `date -d`、`stat -c`、`find -printf`、`find -maxdepth`
- `grep -P`、`tail -F`、`sort -z`、`xargs -r`
- `sed -i` 的参数形式、`du --max-depth`
- Bash 的数组、`[[ ]]`、`source`、`pipefail`、进程替换 `<(...)`
- Vim 的 `gg`、可视块、文本对象、窗口、标签页和系统剪贴板

自动化应明确目标平台，在 CI/镜像中锁定工具版本，或只使用经过验证的共同子集。最小容器常只有 BusyBox，同名命令的输出和选项不能假定与 GNU 一致。

### 22.4 传统与现代命令对照

| 传统/兼容命令 | 现代常用工具 | 说明 |
| --- | --- | --- |
| `ifconfig` | `ip address` / `ip link` | 地址与链路 |
| `route` | `ip route` | 路由表 |
| `arp` | `ip neigh` | ARP/NDP 邻居 |
| `netstat` | `ss` | socket 统计 |
| `service` / `chkconfig` | `systemctl` | 仅 systemd 环境；语义不完全一一对应 |
| `egrep` / `fgrep` | `grep -E` / `grep -F` | 更明确，避免弃用别名警告 |

### 22.5 高风险命令执行清单

涉及 `rm` 递归删除、`dd`、`mkfs`、分区、`wipefs`、文件系统修复、LVM/RAID、递归权限、用户目录删除、防火墙、SSH、内核模块或全局 sysctl 时，至少回答：

1. 精确目标是什么，如何用两个独立标识确认？
2. 当前状态和期望状态是什么？
3. 权限、挂载、符号链接、namespace 和自动化变量会不会扩大范围？
4. 是否有经过恢复测试的备份或配置副本？
5. 会中断哪些进程、会话、网络路径或集群成员？
6. 如何 dry-run/只读预览？哪些命令实际上会修改状态？
7. 成功如何验证，失败如何回滚，失联如何进入控制台？
8. 是否需要变更审批、双人复核、维护窗口和审计记录？
