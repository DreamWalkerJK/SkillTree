# 使用 .NET MAUI 的企业应用程序模式

本文依据 Microsoft Architecture Center 的“.NET MAUI 企业应用程序模式”资料，说明如何组织跨平台客户端、共享领域代码和后端服务。示例以 **.NET 10、.NET MAUI 10、C# 14** 编写；**.NET MAUI 首次随 .NET 6 发布**，需要长期支持时可选择 **.NET 8 LTS**。移动平台 SDK 和商店工具链有独立版本，发布前必须按 Android/iOS/Windows 的支持矩阵验证；不把 .NET 11 预览 API 当作生产依赖。

> 主要参考：[使用 .NET MAUI 的企业应用程序模式](https://learn.microsoft.com/zh-cn/dotnet/architecture/maui/)。

## 1. 适用场景和总体架构

.NET MAUI 适合需要共享 C# 业务逻辑、同时运行在 Android、iOS、Windows 和 macOS 的企业应用。它不是把桌面窗口简单缩放到手机，而是共享领域和基础设施代码，在各平台保留符合平台习惯的导航、权限和生命周期处理。

```text
                 ASP.NET Core API / BFF
                  |       |       |
              SQL/缓存  消息总线  文件存储
                  ^       ^       ^
          HTTPS + OAuth 2/OIDC + 推送服务
                  |
       .NET MAUI 客户端（Shell + MVVM）
       +-------------------------------+
       | 共享领域/应用层（.NET Standard）|
       | 数据同步、缓存、遥测、验证      |
       +-------------------------------+
       | Android | iOS | Windows | macOS |
```

推荐把服务端 API 和移动客户端分成独立发布单元。客户端只缓存必要数据，所有权限在服务端再次校验。离线能力通过本地 SQLite、变更日志和同步冲突策略实现，不要把本地数据库当成最终权威数据源。

## 2. 解决方案布局

```text
src/
  FieldOps.App/             # .NET MAUI 启动项目、Shell、平台代码
  FieldOps.Core/            # 实体、值对象、用例接口（无 UI 依赖）
  FieldOps.Infrastructure/  # HTTP、SQLite、令牌、遥测
  FieldOps.Api/              # ASP.NET Core 后端
tests/
  FieldOps.Core.Tests/
  FieldOps.Infrastructure.Tests/
  FieldOps.App.Tests/
```

UI 采用 MVVM（Model-View-ViewModel）或 CommunityToolkit.Mvvm。视图只负责绑定和导航，ViewModel 负责编排用例，Core 层不引用 `Microsoft.Maui.*`。平台特定代码通过接口和条件编译隔离：

```csharp
public interface IDeviceInfo
{
    string Platform { get; }
    string AppVersion { get; }
}

// 共享实现适用于所有 MAUI 目标；需要读取平台专属信息时可在 Platforms/* 中替换。
public sealed class MauiDeviceInfo : IDeviceInfo
{
    public string Platform => DeviceInfo.Current.Platform.ToString();
    public string AppVersion => AppInfo.Current.VersionString;
}

// Platforms/Android/PlatformDeviceInfo.cs
#if ANDROID
public sealed class PlatformDeviceInfo : IDeviceInfo
{
    public string Platform => "Android";
    public string AppVersion =>
        Android.App.Application.Context.PackageManager!
            .GetPackageInfo(Android.App.Application.Context.PackageName!, 0)!
            .VersionName!;
}
#endif
```

在 `MauiProgram` 注册实现：

```csharp
public static class MauiProgram
{
    public static MauiApp CreateMauiApp()
    {
        var builder = MauiApp.CreateBuilder();
        builder.UseMauiApp<App>()
            .UseMauiCommunityToolkit();
        builder.Services.AddSingleton<MainPage>();
        builder.Services.AddTransient<OrdersViewModel>();
        // 共享注册可在 Android/iOS/Windows/macOS 构建；平台专属实现应通过条件编译替换。
        builder.Services.AddSingleton<IDeviceInfo, MauiDeviceInfo>();
        // 从 appsettings.json、环境配置或安全配置中心读取；不要把生产地址硬编码在客户端。
        var apiBaseUrl = builder.Configuration["Api:BaseUrl"]
            ?? throw new InvalidOperationException("缺少 Api:BaseUrl 配置");
        builder.Services.AddSingleton(new HttpClient
        {
            BaseAddress = new Uri(apiBaseUrl, UriKind.Absolute)
        });
        return builder.Build();
    }
}
```

实际项目应使用 `IHttpClientFactory` 或命名客户端，并从安全配置加载 API 地址；上面的固定地址只为展示注册关系。

## 3. Shell 导航与页面状态

Shell 在 .NET MAUI 中提供路由、导航和深层链接。页面导航参数使用强类型对象或查询属性，不要把敏感数据拼接进 URL：

```csharp
public partial class OrderDetailsViewModel : ObservableObject,
    IQueryAttributable
{
    [ObservableProperty] private Guid orderId;
    [ObservableProperty] private OrderDto? order;

    private readonly IOrderService _service;
    public OrderDetailsViewModel(IOrderService service) => _service = service;

    public void ApplyQueryAttributes(IDictionary<string, object> query)
    {
        if (query.TryGetValue("id", out var value) && value is Guid id)
            OrderId = id;
    }

    [RelayCommand]
    private async Task LoadAsync(CancellationToken cancellationToken)
        => Order = await _service.GetAsync(OrderId, cancellationToken);
}
```

```csharp
Routing.RegisterRoute("order-details", typeof(OrderDetailsPage));
await Shell.Current.GoToAsync("order-details", new Dictionary<string, object>
{
    ["id"] = orderId
});
```

页面离开时取消未完成请求，防止 ViewModel 被销毁后继续更新 UI。`AsyncRelayCommand`（CommunityToolkit.Mvvm）可以自动管理执行状态和取消令牌；不要在构造函数中执行异步 I/O。

## 4. MVVM、验证和状态管理

```csharp
public partial class LoginViewModel(
    IAuthService auth,
    INavigationService navigation) : ObservableValidator
{
    [ObservableProperty]
    [Required, EmailAddress]
    private string email = "";

    [ObservableProperty]
    [Required, MinLength(8)]
    private string password = "";

    [RelayCommand]
    private async Task SignInAsync(CancellationToken ct)
    {
        ValidateAllProperties();
        if (HasErrors) return;
        await auth.SignInAsync(Email, Password, ct);
        await navigation.GoToAsync("//home");
    }
}
```

短期页面状态放在 ViewModel；跨页面状态（当前用户、租户、同步状态）放在作用域服务；可恢复状态写入安全存储或 SQLite。`Preferences` 只适合非敏感设置，令牌使用平台安全存储（Android Keystore、iOS Keychain、Windows Credential Locker）。

## 5. HTTP、认证和安全存储

使用 OAuth 2.0/OIDC 的授权码 + PKCE 流程，移动端不要保存客户端密钥。`WebAuthenticator` 负责系统浏览器登录，令牌缓存到 `SecureStorage`：

```csharp
public sealed class TokenStore
{
    private const string AccessTokenKey = "access_token";

    public Task<string?> GetAsync() => SecureStorage.Default.GetAsync(AccessTokenKey);

    public Task SetAsync(string token) =>
        SecureStorage.Default.SetAsync(AccessTokenKey, token);

    public void Clear() => SecureStorage.Default.Remove(AccessTokenKey);
}
```

生产代码应使用 MSAL.NET（Microsoft.Identity.Client）管理访问令牌、刷新和账户退出，并设置令牌的最小作用域。API 端验证签发者、受众、签名、过期时间和权限；客户端隐藏按钮只能改善体验，不能替代服务端授权。

## 6. 离线优先和同步

离线模式通常采用“本地写入队列 + 后台同步”：

```csharp
public sealed class SyncService(
    LocalDb db,
    IRemoteOrdersApi api,
    ILogger<SyncService> logger)
{
    public async Task PushAsync(CancellationToken ct)
    {
        var pending = await db.PendingOperationsAsync(ct);
        foreach (var op in pending)
        {
            try
            {
                await api.ApplyAsync(op, ct); // 使用 IdempotencyKey
                await db.MarkCompletedAsync(op.Id, ct);
            }
            catch (ApiConflictException ex)
            {
                await db.MarkConflictAsync(op.Id, ex.ServerVersion, ct);
            }
            catch (HttpRequestException ex)
            {
                logger.LogWarning(ex, "网络不可用，稍后重试");
                break;
            }
        }
    }
}
```

每个操作携带客户端生成的幂等键、实体版本和时间戳。服务器使用乐观并发（ETag/`rowversion`）检测冲突，返回可供用户选择的差异；不要用“最后写入覆盖”悄悄丢失现场数据。同步任务应在 `Connectivity.Current` 恢复、应用启动和系统允许的后台窗口触发，避免无限后台运行耗尽电量。

## 7. 设备能力、权限和推送

平台权限在使用前请求并解释用途；Android/iOS 的权限名称和生命周期不同，封装在 `IPermissions` 服务中。相机、定位、蓝牙等能力应设置最小权限和超时。

推送通知采用 Azure Notification Hubs 或平台原生服务。设备令牌可能变化，服务器保存最新令牌并允许撤销；通知内容不要携带密码、完整个人信息或可直接执行的命令。点击通知后通过安全的业务 ID 查询服务器数据，并再次执行授权。

## 8. 性能和资源管理

- 使用 `CollectionView` 虚拟化长列表，图片设置尺寸、缓存和缩略图；不要一次加载原图。
- 网络调用全部异步，设置取消令牌、超时和有限重试；应用切到后台时取消非关键请求。
- 释放 `Stream`、数据库连接、订阅和 `IDisposable` 页面资源。事件订阅若跨越页面生命周期，必须在 `Dispose` 中解除。
- AOT、裁剪和单文件发布能减少启动时间和体积，但反射序列化需要保留元数据。发布前运行真实设备测试，确认裁剪没有移除模型。
- 使用 `dotnet-counters`、Android Profiler、Xcode Instruments 和 .NET MAUI 热路径日志定位启动、布局、GC 和网络耗时。

## 9. 测试和交付

1. Core 层单元测试不依赖 MAUI，覆盖业务规则、并发版本和同步冲突。
2. Infrastructure 测试使用本地 SQLite/容器数据库、WireMock.Net 和故障注入验证重试、令牌过期和离线恢复。
3. UI 测试可使用 .NET MAUI Test（或 Appium/Playwright Mobile）覆盖导航、旋转、深层链接、权限拒绝和键盘行为。
4. 在真实 Android/iOS/Windows 设备上执行启动、后台恢复、弱网、电量和推送测试；模拟器不能代表所有硬件行为。
5. CI 构建签名产物，执行 `dotnet build -f net10.0-android`、`net10.0-ios` 等目标，运行静态分析、依赖扫描和许可证检查。
6. 通过 TestFlight、Google Play 内测和 MSIX 渠道分阶段发布，监控崩溃率、ANR、启动时间和 API 错误率，保留可回滚版本。

## 10. 企业治理清单

- 统一应用版本、API 兼容策略和最低支持系统版本。
- 使用 MDM/Intune 下发企业配置、证书和远程擦除策略；个人设备数据与企业数据分区。
- 审计高风险操作，客户端日志默认脱敏；支持用户注销、数据导出和删除请求。
- 记录第三方 SDK、权限和隐私用途，发布前完成应用商店合规审核。
- 对离线数据设定保留期限和加密策略，设备越狱/root 检测只作为风险信号，不作为唯一安全措施。

## 11. 版本提示与官方参考

- .NET MAUI 6（2022-05）：跨平台 UI 框架首个正式版本。
- .NET MAUI 8（2023-11，随 .NET 8 LTS）：稳定的移动/桌面工具链和性能改进。
- .NET MAUI 9（2024-11，STS）：控件、Shell 和构建体验更新。
- .NET MAUI 10（2025-11，当前示例）：对应 .NET 10/C# 14，需匹配各平台 SDK。
- .NET 11（预计 2026-11）：截至本文日期仍为预览版本，部署前需单独验证。
